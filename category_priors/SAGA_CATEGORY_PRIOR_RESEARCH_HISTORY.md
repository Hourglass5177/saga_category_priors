## 0. 先用一分钟说清楚结论

老师最初给我们的想法是：

> 现在的三维高斯实例分割，大多把所有物体当成同一种“特征聚类”问题处理。其实不同类别有不同的常见大小、表面平滑程度和小物体特性，应该把这些类别知识用进去。

老师交给我们的并不是一套已经完成、已经在通用数据集上显著提升的“全类别参数表”。老师交付的是：

- 一套能在办公室场景运行的工程代码；
- 一条四阶段命令；
- 一个名为 `other_classes` 的小物体特殊分支；
- 一个值得继续研究的方向。

从那以后，我们做了很多轮实验。现在最重要的总判断是下面五点：

1. **老师的小物体分支确实会改变结果，也会救回个别小物体。**
   在 48 个场景、3 个随机种子上，它让宽松指标 AP25 提升约 `0.01145`，AP50 提升约 `0.00445`，但历史十门槛严格平均指标只提升 `0.000825`，而且只有 1/3 个种子方向为正。

2. **我们早期几种“数据驱动类别先验”实现确实失败了。**
   其中最可信的具体映射负结果是 `prior-v2`：它的绝对指标与 B0/B1 同一数量级，而且统一组和数据组结构相同；数据驱动尺寸先验最终比统一参数低 `0.000444`，置信区间跨过 0。这个结果说明“当时那套统计量到运行参数的映射”没有稳定价值，但不等于旧主干已经完全健康。

3. **原生提示式尺寸先验已经得到一条很直接的负证据。**
   在对象身份和类别已知、提示完全相同的 8 个物理场景和 124 个对象上，逐类典型包围盒尺寸确实改变了尺度门和最终掩码，但场景等权 IoU 差约为 `-0.0000474`。九点尺度网格的理想选择上界也只有 `+0.003673`；两场 10k 正控没有扩大容量。这个结果有力否定“完整物体典型尺寸直接控制当前 SAGA 尺度门”这条具体路线。

4. **后来的许多自动路线没有走到公平检验类别先验那一步。**
   候选形成追踪显示 8 场冻结池的 1,344 个候选中只有 15/4 个达到同类 IoU≥0.25/0.50。HDBSCAN 重分配确有错误，但修正距离、锚定原始成员和互选图都没能恢复健康候选。干净掩码基线证明二维输入里存在大量完整物体支持，自动跨视角关联和对象重建却没有把上界转化成实例。

5. **原始自动实例分割基线本身确实有严重结构问题，而我们自己的实验工具也曾造成误判。**
   基线问题包括错误的最大贡献高斯映射、空像素错误指向第 0 个高斯、全场 K 近邻改写、全点向中心吸附、类别过早切分又被最后投票改写、输出标签和实例元数据“两套真相”等。我们自己的比较器也曾把 31 点元数据差异误报为 370,226 点变化，运行器和多轮候选评价还出现过接口错误。老师的早期代码更像研究原型，而不是一个已经验证健康的自动 ScanNet 实例分割系统；但纠正后的证据必须与这些自有错误严格分开。

因此，截至 2026-09-02，最准确的说法是：

> **老师“类别知识可能有用”的总假设没有被完整证伪，但当前尺寸类接口和多种统计映射的证据明显偏负。自动实例路线的最大已知瓶颈，是把不同视角里的二维物体观察组成完整、干净的三维对象。是否继续重建这个主干，已经不是一个默认的技术下一步，而是需要导师明确批准的课题范围选择。**

## 1. 老师到底让我们做什么

### 1.1 老师原话拆解

老师在 7 月 24 日的聊天中说：

> “3DGS 实例分割时候，现在方法都没有用到这个语义物体的先验，比如他的一般大小，他的平滑程度等等……应该用到语义的先验，而不是只把他当一个单纯的特征分割来干。”

随后老师又补充：

> “代码里面我们也分了一个额外的 other class 专门处理这种小物件……还能往下挖一下，然后放通用数据集上做实验，然后也证明有效。”

完整聊天见[和王教授的聊天记录](../../.agents/和王教授的聊天记录.md)。

老师原话明确要求我们跑通工程、继续深挖小物件和语义物体知识，并放到通用数据集验证。为了把这个宽泛方向变成可执行实验，**我们后来选择**把它具体化为四件事：

1. **先把老师给的工程跑起来。**
2. **弄懂老师早期的小物体特殊分支到底做了什么。**
3. **把模糊、共享的人工规则推广成全类别、数据驱动的类别知识。** 这是我们的研究方案，不应反过来写成老师已经指定了完整做法。
4. **在通用数据集上证明它是否真的有效，而不是只看一个办公室场景。**

### 1.2 老师没有交付什么

仓库和聊天里没有以下东西：

- 没有 20 类或 32 类各自一套完整手工参数；
- 没有“全类别人工先验显著提升”的可复现实验命令；
- 没有对应的通用数据集指标表；
- 没有一个能和当前 ScanNet 自动实例分割指标直接比较的公开 SAGA 官方数值。

老师的 `other_classes` 是一种早期启发式：对少数容易被统一聚类吞掉的小物类别，单独按类别筛点和聚类。可见的 `source/a800` 默认列表有 7 类：

- 插座；
- 书；
- 遥控器；
- 钥匙；
- 杯子；
- 花瓶；
- 手机。

当前 32 类资产兼容路径后来把开关也计入，文档里常简称“原 8 类分支”。因此“7 类还是 8 类”的差异来自版本和词表兼容，不代表老师已经有一套全类别规则。

### 1.3 我们后来把任务做大了

公开 SAGA 的原始目标主要是“给一个二维提示，在三维高斯场景中找对应对象或区域”。它更像：

> 用户指着图里一个物体问：“把这个东西在三维里选出来。”

而我们后来做的是：

> 不给人工提示，让系统自动找出整个场景中的所有目标，给每个目标分实例、判类别、打分，再按 ScanNet 协议算平均精度。

这叫**闭集自动三维实例分割**：

- “闭集”表示类别名单事先固定；
- “自动”表示没有用户逐个点选物体；
- “实例分割”表示不仅要知道“这是椅子”，还要分清“第一把椅子”和“第二把椅子”。

这比公开 SAGA 的提示式任务难很多。因此，公开 SAGA 的论文结果只能帮助我们理解表示和结构，不能直接拿来和本项目的 `0.05` 左右平均精度横向比较。

公开实现的典型流程是：用 SAM 全部分割生成掩码，训练约 10k 次实例关联特征，再在图形界面或笔记本中通过点击提示选择对象。它没有直接提供“整场自动找出全部实例、给每个实例打检测分数、按 ScanNet 闭集协议算 AP”的官方基线。

## 2. 先把整个流水线讲成人话

老师给的四条命令，对应下面四步。仓库说明见[根目录 README](../README.md)。

```text
多张房间照片
    ↓
第一步：在每张照片里画出物体区域，并写上类别
    ↓
第二步：估计这些二维区域在三维里大概有多大
    ↓
第三步：让每个三维高斯学会“我和谁属于同一个物体”“我像什么类别”
    ↓
第四步：把高斯聚成一个个实例，判类别，输出结果
```

### 2.1 什么是三维高斯

3DGS 是“三维高斯泼溅”的缩写。可以把一个场景想成由很多半透明、带颜色的小椭球组成。每个小椭球就是一个高斯。

它不是 ScanNet 标注里的原始网格顶点，也不是普通点云点。一个真实物体通常由许多高斯共同表示；一张图里的一个像素也可能同时由前后多个半透明高斯贡献。

### 2.2 什么是二维掩码

“掩码”就是一张黑白区域图：

- 白色表示“这个像素属于目标”；
- 黑色表示“不属于目标”。

Grounded-SAM 把类别文字检测和 SAM 分割组合起来。例如输入“椅子”，它先找椅子的框，再切出椅子的像素区域。

SAM-everything 则是不先问类别，尽可能把图中可分的区域都切出来。它的好处是覆盖更多，坏处是会产生很多层级重叠和碎片。

### 2.3 什么是“从二维提升到三维”

英文常叫 `lifting`，本文统一称“二维到三维提升”。

它要回答：

> 二维掩码里的这个像素，主要对应哪个三维高斯？

如果这个对应关系错了，即使二维掩码很好，三维结果也会被污染。

### 2.4 什么是实例特征、语义特征和尺度门

- **实例特征**：帮助判断两个高斯是不是同一个具体物体。
- **语义特征**：帮助判断高斯像椅子、桌子还是杯子。
- **尺度门**：不同观察尺度下选择合适的特征通道。

可以把它们理解成三种线索：

- “长得是不是同一件东西”；
- “属于什么类别”；
- “应该用多大的观察尺子看”。

### 2.5 什么是聚类

聚类就是在没有实例编号答案的情况下，把相似的高斯自动分组。

本项目大量使用 HDBSCAN。它是一种“找密集人群”的算法：

- 一堆靠得近、特征相似的点会被视为一组；
- 太稀疏的点会被视为噪声；
- `min_cluster_size` 控制最小组规模；
- `min_samples` 控制多严格地把点视为核心点。

它本身不知道“这是椅子”，也不知道“这个小簇其实是插座”；参数选错时，小物体会被当成噪声，大物体会被切碎或粘在一起。

### 2.6 什么是 K 近邻

K 近邻，简称 KNN，意思是“看每个点附近的 K 个邻居，按邻居多数决定它的标签”。

它像一次全场投票清洗：

- 好处：能抹平零碎噪点；
- 坏处：小物体周围大多是墙或大物体，少数小物体点很容易被多数票吞掉。

老师的小物体特判正是想缓解这种问题。

### 2.7 什么是类别先验

“先验”不是神秘模型，而是算法运行前就知道的常识。例如：

- 杯子通常不会和床一样大；
- 墙通常面积大、连续而平滑；
- 插座和开关通常很小，不能用对桌子有效的最小簇门槛；
- 有些类别边界复杂，不能用过大的邻域强行平滑。

我们主要从 ScanNet 训练集提取过三类统计：

1. **尺寸**：包围盒对角线、表面积、体积；
2. **边界与平滑性**：一定物理半径内，邻点有多少仍属于同一实例；
3. **小物体支持度**：典型表面积和场景高斯密度共同决定一个合理实例应有多少高斯。

稀有类别的数据少，所以曾用“向父类或全局统计收缩”的办法，避免用两三个样本估出离谱参数。

## 3. 指标怎么读，为什么肉眼提升和 mAP 很低可以同时成立

### 3.1 交并比

交并比，英文缩写 IoU，用来衡量预测实例和真实实例重合得有多好。

假设真实杯子有 100 个评估点：

- 预测对了 60 个；
- 多画了 40 个不属于杯子的点；
- 漏了 40 个真实杯子点。

那么交集是 60，并集是 140，交并比约为 `60/140=0.429`。

这个实例能通过 0.25 门槛，但通不过 0.50 门槛。

### 3.2 AP25、AP50 和严格平均精度

- **AP25**：用 0.25 作为预测与真实实例的交并比匹配门槛，比较宽松；
- **AP50**：用 0.50 作为匹配门槛，严格一些；
- **历史十门槛严格平均**：从 0.50、0.55 一直到 0.95，共十个门槛分别算平均精度，再取平均；历史代码字段名是 `map_50_95`。

注意，AP 不是“达到交并比门槛的实例比例”。评估还会按预测分数排序，重复预测和假阳性会被扣分，再对“精确率—召回率曲线”求面积。交并比门槛只决定一个预测能不能和某个真实实例匹配。

还要区分两个协议：

- **ScanNet 官方九门槛实例平均**：0.50、0.55，直到 0.90；
- **本项目历史十门槛平均**：在上述基础上又加入 0.95。

本文沿用 B0/B1、B2、prior-v2 等历史结果时，除非明确写“官方九门槛”，所谓“严格平均精度”都指历史十门槛字段。原始基线闭环后来会同时报告两套数值，不能把十门槛字段直接称为 ScanNet 官方平均。

所以一个方法可能：

- 肉眼上确实多找到了杯子；
- AP25 提高；
- 但边界太脏、漏点太多，AP50 和严格平均精度不升。

老师早期 B1 的表现正是这样。

### 3.3 准确率和召回率

这里使用“准确率”时，更精确的名称是**精确率**：

- **精确率**：系统说属于这个物体的高斯中，有多少真的属于它；
- **召回率**：真实物体中，有多少被系统找回。

生活类比：

- 一张渔网只捞到一条鱼，但没捞到垃圾：精确率高、召回率低；
- 一张大网把鱼和水草全捞上来：召回率高、精确率低。

老师后来提醒“主要是准确率，不是召回率”，就是要求我们从“系统切出来的高斯到底干不干净”这一侧审计，而不是只看真实物体有没有碰到一些预测点。

### 3.4 为什么传统评估会看不见一部分污染

早期评估主要把每个真实 ScanNet 顶点映射到最近的高斯，再看这个顶点得到什么预测标签。这样容易看见“真实物体有没有被覆盖”，但不容易看见：

- 某个预测实例额外吞了大量没有真实顶点支持的高斯；
- 某些高斯根本离所有真实点很远；
- 预测实例在高斯空间很脏，但映射到稀疏真实点后污染被压缩了。

因此后来增加了“预测高斯到真实点”的精度审计。它不替代官方指标，而是补上官方指标看不清的污染。

## 4. 老师原始基线到底是什么

### 4.1 B0：不启用小物体特殊分支

B0 的流程可以简化成：

```text
全场采样
  → 用实例特征和空间距离聚类
  → 所有点吸附到聚类中心
  → 全场 K 近邻平滑
  → 删除过小实例
  → 用二维标签投票决定每个实例类别
```

### 4.2 B1：启用老师的小物体特殊分支

B1 在 B0 中间插入一个分支：

```text
先跑全场通用聚类
  +
对少数小物类别分别做：
  语义相似度筛点
  → 类内采样
  → 混合实例/空间/语义距离聚类
  → 全量候选点吸附到类别簇
  → 合并回全场
  → 仍然经过全场 K 近邻、最小簇过滤和最终类别投票
```

这个分支的重要特点是：

- 它证明老师确实在尝试“类别特殊化”；
- 但所有小类共享一套参数；
- 语义相似度门槛统一为 0.7；
- 每类最多采样 5,000 个高斯，最小簇统一为 5；
- 实例特征、空间和语义距离权重统一为 0.5/0.3/0.2；
- 空间坐标先按整场最小值和最大值归一化，并没有使用“杯子多少米、床多少米”的逐类物理尺度；
- 分支结果后面仍可能被统一 K 近邻和过滤吞掉；
- 最后类别投票还能把分支原本的类别改掉。

### 4.3 B0/B1 的正式复评结果

在 48 个不同物理场景、3 个随机种子上的平均结果：

| 指标 | B0 | B1 | B1−B0 |
|---|---:|---:|---:|
| 历史十门槛严格平均精度 | 0.055338 | 0.056164 | +0.000825 |
| AP50 | — | — | +0.004449 |
| AP25 | — | — | +0.011450 |

三个随机种子的严格平均精度差值分别是：

- 种子 42：`−0.000009`；
- 种子 3407：`−0.000210`；
- 种子 20260804：`+0.002694`。

这说明：

- 小物分支不是“完全没运行”；
- 它更容易改善宽松覆盖；
- 严格收益不稳定，不能叫“显著有效”。

### 4.4 两场景高斯精度审计

两场景直接检查预测高斯：

| 指标 | B0 | B1 |
|---|---:|---:|
| 高斯到真实实例的微平均精确率 | 20.36% | 20.40% |
| 实例精确率中位数 | 0 | 0 |
| 无真实支持的预测实例 | 15/27 | 16/29 |

B1 新增的两个书本实例很有代表性：

- 一个实例有 762 个高斯，精确率 59.84%，召回率 67.94%，交并比 0.434：它能提高 AP25，但达不到 AP50；
- 另一个实例有 84 个高斯，精确率、召回率和交并比都是 0：它是纯假阳性。

所以老师肉眼看到的现象和指标并不矛盾：**小物体确实可能被救回来，但垃圾实例也一起被救回来了。**

### 4.5 对原始基线的正确判断

能说：

- 老师的小物体特判有真实、但很弱的宽松指标信号；
- 原始自动主干的实例质量很差；
- 老师给的是一个值得研究的原型。

不能说：

- 老师已经证明全类别人工先验显著有效；
- B1 是一个健康的自动实例分割强基线；
- B1 收益弱就说明所有类别先验都没用。

## 6. 第一轮：先把研究做成可评测实验

### 6.1 当时想解决什么

老师只有办公室数据和工程流程。要回答“类别先验是否有效”，我们必须先建立：

- 通用数据集；
- 训练统计和验证场景的隔离；
- 统一的三维真实标注；
- 可重复的三维实例指标，并在后续闭环中区分官方九门槛和历史十门槛；
- 足够多的场景，避免只看一个漂亮案例。

因此我们选了 ScanNet，并把数据分成：

- **训练集**：只用来计算类别统计；
- **24 个调试场景**：选择方法和全局参数；
- **48 个内部评估场景**：最后做一次集中验证。

后来又准备了约 73 套可复用场景资产，包括 30k 三维高斯、相机、掩码、标签、特征、尺度门和真实标注。

### 6.2 做了哪些统计

我们从 ScanNet 训练集的真实实例网格中提取：

- 典型包围盒长宽高和对角线；
- 典型表面积和体积；
- 在 2、5、10、20 厘米邻域里的同实例比例；
- 边界点比例；
- 每个类别出现过多少实例、多少物理场景。

为了防止稀有类别参数过激，又加入了可靠性和向全局统计收缩。

### 6.3 这一阶段的价值

这一阶段完成了很多必要但“不直接提高精度”的基础工作：

- ScanNet 数据准备；
- 坐标和米制尺度对齐；
- ScanNet 风格评估器，以及后来补齐的官方九门槛/历史十门槛双协议报告；
- 场景级重采样；
- 随机种子复核；
- 可恢复云端运行；
- 训练集、调试集和最终内部评估集隔离。

这些工作让后面所有失败都有可比较数字，而不是只靠肉眼。

### 6.4 当时埋下的问题

第一版研究设计太快把很多东西绑到了一起：

- 候选怎么生成；
- 先验怎么映射；
- 是否启用可靠性门；
- 是否做统计收缩；
- 如何覆盖旧标签；
- 如何平滑和过滤。

这使得后面 B2 的“统一参数组”本身已经不是老师的 B0/B1 主干。比较虽然形式完整，却没有做到“只改类别参数，其他完全一样”。

---

## 7. B2：第一版完整数据驱动先验

### 7.1 想解决什么

B2 是第一次把训练集统计完整接入运行时。三个因素是：

- 尺寸；
- 平滑程度；
- 小物体支持。

用三个开关组成八种组合：

```text
P000-B2：保留 B2 的全局统一参数和覆盖式骨架，只关闭三个逐类数据因素
P100：只开尺寸
P010：只开平滑
P001：只开小物体
……
P111：三个因素全开
```

### 7.2 怎么做

B2 用一层“覆盖式分支”加在旧聚类结果上：

1. 先从语义特征中找每个类别的候选点；
2. 根据统计给不同类别分配采样额度和参数；
3. 类别内重新聚类；
4. 把全部候选点吸附到类别簇中心；
5. 用类别分支覆盖旧标签；
6. 再做验证、平滑和最小簇过滤；
7. 不通过验证时回退旧标签。

此外还做了全局参数搜索、先验参数搜索、可靠性门和统计收缩。

### 7.3 实际结果

48 场景、3 个随机种子：

| 条件 | 历史十门槛严格平均精度 |
|---|---:|
| B2 统一结构 `P000` | 0.019761 |
| 三因素全开 `P111` | 0.020532 |
| 差值 | +0.000770 |

看起来 P111 比 P000 好一点，但 B2 的 P000 已经远低于 B0/B1 的 `0.055–0.056`。

### 7.4 为什么失败

根本问题不是“增益不够大”这么简单，而是比较骨架先坏了：

- B2 的统一组也走新覆盖结构，不等于 B0；
- 类别分支会大范围覆盖旧结果；
- 候选生成、回退、门控和统计参数一起变化；
- 后来还发现，某些尺寸差异会被后续最大值归一化削弱；
- 小类别得到更小的最小簇后，仍可能被后续统一 K 近邻或最小簇过滤删除。

### 7.5 这轮证明了什么

证明了：

- 三因素全开的 P111 在 B2 结构内相对 P000 高约 `+0.00077`；这个差值是整个组合的结果，不能拆开说尺寸、平滑、小物体三个单因素分别都有效。

没有证明：

- 类别先验整体有效；
- P111 优于老师原始 B1；
- B2 值得继续作为主干。

准确结论是：

> **B2 这套复杂覆盖结构失败。数据先验只能在一个已经退化的主干上做微弱补偿。**

## 8. class-first：先判类别，再在类别里找实例

### 8.1 为什么提出

B2 太复杂，于是我们尝试一个看起来更直观的思路：

> 既然不同类别应该用不同参数，那先把所有高斯分到类别，再在每个类别内部独立聚类。

英文 `class-first` 就是“类别优先”。

### 8.2 怎么做

1. 让全部 32 个类别一起竞争；
2. 每个高斯只取最像的一个类别；
3. 只在同一类别内部采样和 HDBSCAN 聚类；
4. 只在同一类别内部做 K 近邻；
5. 尺寸、平滑、小物体参数都按类别变化；
6. 噪声点可按同类邻居恢复。

它避免了跨类别 K 近邻，看上去更符合“类别特殊化”。

### 8.3 实际结果

48 场景、3 个随机种子：

| 条件 | 历史十门槛严格平均精度 |
|---|---:|
| 类别优先统一参数 `U0` | 0.000208 |
| 最好的小物体参数 `D-small` | 0.001617 |
| 相对差值 | +0.001409 |

相对差值的置信区间为 `[0.000408, 0.003505]`。如果只看差值，好像“显著提高”了。

但是预测实例数量约为真实实例的 `8.2` 倍，绝对精度几乎是零。

### 8.4 为什么失败

生活类比：系统先给每个人发了一个可能错误的队服，再规定不同队服的人永远不能组队。最开始衣服发错一次，后面就再也救不回来。

具体问题：

- 硬性的 32 类单选把语义错误直接传给实例分割；
- 一个真实物体不同部分如果被判成不同类，会被永远切开；
- 去噪和类内传播会继续放大碎片；
- 救噪声点有时又会错误扩张；
- 结果严重过分割和漏覆盖。

### 8.5 正确结论

`D-small` 相对 `U0` 的正差只能说明：

> 小物体参数在一个已经崩坏的类别优先主干中，能把“几乎完全失败”补成“仍然几乎完全失败”。

它不能支持方法有效。被否定的是这套硬类别优先主干。

---

## 9. prior-v2：回到较强主干，做一次较干净的同结构比较

### 9.1 为什么提出

class-first 的最大问题是主干先崩。因此 prior-v2 回到较接近 B0/B1 的旧主干：

- 全局候选保持不变；
- 全局过滤和二维投票保持不变；
- 类别分支只处理全局没有分配的背景点；
- 不覆盖全局实例；
- 不跨类别平滑；
- 统一组和数据组只差逐类参数。

这是早期实验中最接近“同一道菜只换调味料”的比较。

### 9.2 比较了什么

- `L1-uniform`：所有类别使用共享参数；
- `D-size`：按类别尺寸；
- `D-smooth`：按类别边界和平滑统计；
- `D-small`：按类别典型支持度；
- `D-combined`：三者组合。

### 9.3 调试集结果

24 个调试场景、种子 42：

| 条件 | 历史十门槛严格平均精度 |
|---|---:|
| L1-uniform | 0.064741 |
| D-size | 0.066952 |
| D-smooth | 0.066237 |
| D-small | 0.065512 |
| D-combined | 0.065691 |

单看这个种子，尺寸先验最好。

补齐三个种子后：

- L1：`0.064269`；
- D-size：`0.064942`；
- 平均差：`+0.000673`；
- 置信区间：`[-0.000017, 0.001183]`。

这时信号已经很小，而且区间跨过 0。

### 9.4 48 场景结果

| 条件 | 历史十门槛严格平均精度 |
|---|---:|
| L1-uniform | 0.053637 |
| D-size | 0.053193 |
| 差值 | −0.000444 |

95% 置信区间为 `[-0.001828, 0.000209]`，3 个种子中 2 个方向为负。

### 9.5 为什么这一轮特别重要

这不是“主干只有 0.0002”的 class-first，也不是 B2 那种主干换掉。prior-v2 的绝对性能和 B0/B1 同一数量级，统一组与数据组又使用同一结构，所以这是对**具体数据映射**最有力的负证据；但这不代表旧主干的贡献映射、孤儿标签和实例分数等问题已经消失：

> 用当时的训练集尺寸、平滑、小物体统计，按当时的公式映射到运行参数，不能稳定优于共享参数。

但它仍不能证明：

- 所有类别知识都无用；
- 更好的统计形式无用；
- 类别先验作用在候选评分或对象所有权上也无用；
- 老师可能在办公室场景手工试过的其他规则无用。

---

## 10. teacher-prior：严格回到老师的分支结构做最小复测

### 10.1 为什么提出

用户质疑前面是不是“自作聪明把工作流改坏了”。因此这一轮不再发明新主干，直接使用老师 a800 的原顺序：

```text
全局旧聚类
  → 各类别特殊分支
  → 合并
  → 全场 K 近邻
  → 小簇过滤
  → 二维类别投票
```

先把少数小类扩到 SAGA20 全部评估类别：

- `U0-all-uniform`：全类别走同一分支、共享参数；
- 数据条件：结构完全相同，只替换尺寸、平滑和小物体数值。

### 10.2 原结构的结果

8 场景：

| 条件 | 历史十门槛严格平均精度 |
|---|---:|
| U0 全类别共享参数 | 0.016242 |
| D-size | 0.016369 |
| 差值 | +0.000128 |

数据参数实际改变了约 `0.77%–1.18%` 的高斯划分，说明代码确实执行了，不是“参数根本没传进去”。但它没有通过任一预先登记的扩展门槛：既没有达到总体严格平均精度 `+0.002`，也没有满足“小类别宏平均至少 `+0.005`、总体不低于 `−0.0005`”及场景方向、结构安全等联合条件。

### 10.3 全量保护为什么更糟

我们怀疑类别分支被后面的全场 K 近邻和过滤吞掉，于是试过：

> 只要是类别分支找出的实例，就保护起来，不让后续步骤删除。

结果：

- 原结构 U0：`0.016242`；
- 全量保护 U0：`0.004211`；
- 下降：`−0.012030`；
- 预测实例和真实实例的数量比从约 `2.85` 倍涨到约 `7` 倍。

这说明被后处理删掉的并不全是好小物体，其中有大量碎片、错类和假阳性。

### 10.4 选择性恢复为什么也失败

又试过更保守的规则：

> 一个类别分支实例只要有一个点在全局流程中幸存，就把整簇恢复。

在 `scene0231_00`：

- 严格平均精度从 `0.039120` 降到 `0.016667`；
- 差值 `−0.022454`。

一个幸存点远远不足以证明整个候选是好对象。

### 10.5 这轮真正告诉了我们什么

- 数据参数确实进入了老师原结构；
- 当前映射只造成极小扰动，没有形成有效收益；
- 类别候选不能无条件保护；
- 后续全局步骤既会删真点，也会删大量垃圾点；
- 必须先知道“被删候选到底是不是完整真实对象”。

---

## 11. V3：不再猜，直接追踪候选是怎么死的

### 11.1 为什么提出

前面一直在争论：

> 是不是好小物体已经找到了，只是被 K 近邻和过滤误杀？

V3 不先改方法，而是建立“候选漏斗”，像医院检查病人在哪个环节出问题：

1. 二维掩码有没有覆盖真实物体；
2. 语义有没有认对类别；
3. 类别分支有没有形成候选；
4. 候选与真实物体交并比多少；
5. 候选经过 K 近邻后还剩多少；
6. 过滤和最终投票又杀掉多少。

### 11.2 24 场景候选质量

共有 3,202 个只来自类别分支的候选：

- 同类别且交并比达到 0.25：78 个，精确率 `2.44%`；
- 同类别且交并比达到 0.50：15 个，精确率 `0.47%`。

也就是说，一百个候选里，真正达到宽松 0.25 标准的只有两三个；达到 0.50 的不到一个。

这强烈反驳了一个过于简单的想象：

> “候选总体已经很好，主要只是被 K 近邻误杀。”

事实是：类别分支产生的候选总体质量很低，不能靠“全部保护”解决。这里的 3,202 个数字统计的是全部独占候选；如果要把问题单独归因于 K 近邻，还需要按候选具体死亡阶段分别统计交并比。

### 11.3 多锚点保护

为了不再“一点幸存就恢复整簇”，V3 要求：

- 多个幸存锚点；
- 同一候选；
- 同一类别；
- 二维投票确认；
- 只恢复物理半径内的邻近点。

8 场景结果：

| 条件 | 历史十门槛严格平均精度 | 每场实例数 |
|---|---:|---:|
| B1 exact | 0.057953 | 15.125 |
| 统一多锚点保护 | 0.030383 | 36.5 |

覆盖率相近，实例数却翻倍以上，说明主要是过分割和假阳性。

同一个坏保护结构里，数据条件比统一条件高 `0.002679`，但它无法抵消主干损失 `−0.02757`。这种“坏主干里的相对胜利”不能叫方法有效。

### 11.4 最严格的离线补背景

我们又只接纳 2 个高置信候选，而且只填 B1 的背景点：

- AP25：`0.216769 → 0.220737`；
- AP50：`0.188675 → 0.187022`；
- 严格平均精度：`0.057953 → 0.057622`；
- 差值：`−0.000331`。

它又一次呈现同样模式：宽松覆盖略好，严格对象质量略差。

### 11.5 输入上限

对真实小物体检查二维和语义覆盖：

| 分层 | 二维掩码覆盖 | 语义第一名召回 |
|---|---:|---:|
| 极小实例 | 17.97% | 13.96% |
| 小实例 | 27.08% | 21.27% |

这意味着一个真实小物体往往只有约五分之一到四分之一被正确输入覆盖。后处理无法凭空补出完全没出现的部分。

### 11.6 V3 的结论

被否定：

- 多锚点保护；
- 严格的背景补全；
- “主要是全场 K 近邻错杀好候选”的简单解释。

没有被否定：

- 类别先验；
- 在健康候选池上保护小物体；
- 更好的二维输入和跨视角对象构造。

## 12. V4：先查特征训练够不够，再查类别候选

### 12.1 两场景 2k 对 10k 正控

公开 SAGA 常用 10k 次特征训练，而部分现有资产只有约 2k 次。V4 先问：

> 是不是训练轮数太少，导致实例和语义特征没学好？

在两个场景把特征从头训练到 10k，不覆盖原资产。

结果：

- 语义第一名召回平均只提高 `0.00939`；
- 极小/小实例候选 Recall@0.25 反而下降 `0.15`；
- 新增 IoU≥0.25 匹配为 0；
- 一个场景损失 3 个原匹配；
- 候选精确率从 `0.0977` 降到 `0.0737`。

因此，简单把同一种监督训练更久，没有改善这两个正控场景。它不能证明所有 10k 训练都没用，只能说明当时没有理由把昂贵训练扩到全部场景。

### 12.2 八场景类别候选两因素实验

四个条件：

- 统一参数；
- 类别尺度门；
- 类别核心点数量；
- 两者组合。

| 条件 | 小物 Recall@0.25 | Recall@0.50 | 候选数 | 候选精确率@0.25 |
|---|---:|---:|---:|---:|
| 统一 | 0.15190 | 0.05063 | 599 | 0.03339 |
| 类别尺度 | 与统一相同 | 与统一相同 | 权威摘要未记录精确值 | 权威摘要未记录精确值 |
| 类别核心 | 0.12658 | 0.03797 | 448 | 0.04018 |
| 组合 | 0.12658 | 0.03797 | 450 | 0.04000 |

类别核心通过删除更多候选把精确率从约 3.3% 提到 4.0%，但召回下降，没有新增真实匹配。类别尺度的召回与统一条件相同，新增匹配为 0、正向场景为 0，几乎没有形成有用干预。

### 12.3 V4 的结论

- 10k 延长训练没有通过正控门槛；
- 类别尺度和类别核心映射没有改善融合前候选；
- 三个数据条件都没有通过预先登记的联合门槛：召回没有改善、没有新增真实匹配、正向场景也不足；
- 只有 3%–4% 的低绝对候选精确率，进一步说明候选池本身不健康；
- 因此没有进入 24/48 场景，也没有完成健康候选上的类别先验检验。

## 13. V5：把类别先验后移到“候选是否接纳”

### 13.1 为什么提出

V4 直接让类别统计改变候选生成，但候选本身太差。V5 换了一个更公平的位置：

> 先用完全相同的方法生成候选，冻结候选，再让类别先验只决定“这个候选要不要接受”。

这里的“候选”英文常叫 `proposal`，就是“系统认为可能是一个物体的一组高斯”，但它还没有获得正式实例身份。

### 13.2 怎么做

- B1 输出完全旁路保留；
- 候选阶段不改 B1；
- 比较两种语义来源：
  - `codebook`：把高斯语义特征与类别编码表比较；
  - `multiview`：把多张图里的类别投票累计到高斯；
- 全部 32 类共同竞争，只允许 SAGA20 评估类进入候选；
- 候选冻结后，计划比较：
  - 全局统一尺寸和支持；
  - 类别尺寸；
  - 类别核心支持；
  - 两者组合；
- 融合只允许补 B1 背景，不覆盖已有前景。

### 13.3 实际结果

- 两场景旁路检查通过，证明 V5 没有意外改写 B1；
- 8 场景中，编码表来源只有 5 个同类别 IoU≥0.50 候选；
- 多视角来源为 0；
- 没达到绝对候选门槛；
- 因此没有运行融合、轻量分类器、24 场景或 48 场景。

### 13.4 后来发现的问题

V7 后来发现，多视角来源依赖的“最大贡献高斯”底层实现有错误：

- 本应按 `alpha × T_prev` 判断该像素中谁贡献最大；
- 历史实现实际按 `alpha × T_new`；
- 空像素还会默认指向第 0 个高斯。

所以 V5 的多视角结果不仅候选少，其输入对应关系也受污染。

### 13.5 正确结论

V5 证明当时实现没有通过候选门槛：编码表候选的供给确实不足；多视角结果则受到后来发现的贡献映射错误混杂，不能单独用来评价多视角方法本身的潜力。V5 因此没有继续计算的价值，但类别先验四个比较条件根本没有执行，所以它没有公平检验类别先验。

## 14. V6：实例特征优先的局部图

### 14.1 为什么提出

V5 仍然先按语义类别筛点。语义一旦认错，真实对象会被拆开。V6 尝试：

> 先不管是什么类别，只根据实例特征和物理邻近关系把点连成对象；对象形成后再判类别。

### 14.2 怎么做

1. 每个高斯找物理上最近的 24 个邻居；
2. 从中保留实例特征最相似的 4 个；
3. 只有双方都选中对方，才保留这条边；
4. 连通的一组点作为候选；
5. 内部至少有 3 条边的点叫核心点；
6. 候选形成后才做多视角类别投票。

### 14.3 原掩码结果

8 场景：

- 产生 32,709 个候选；
- 候选中位数只有 22 个高斯；
- 同类别 IoU≥0.25 候选为 0；
- 极小/小物体 SAM 中位覆盖只有 `16.915%`；
- 局部实例特征区分同实例和异实例边的面积指标约 `0.65739`。

### 14.4 降低二维检测门槛

把 GroundingDINO 的框和文字阈值从 0.35 降到 0.25：

- 中位覆盖提高到 `25.991%`，增加约 9.08 个百分点；
- 候选数反而增至 35,694；
- 候选中位数仍为 22；
- 同类别 IoU≥0.25 仍为 0。

“三万多个候选、中位只有 22 个高斯”直接说明这套局部图发生了极端碎片化。但“同类别匹配为 0”还依赖对象形成后的多视角类别投票；这部分后来被确认受到错误贡献映射和空像素编号影响。因此，不能把所有零匹配都单独归因于实例特征图。

### 14.5 为什么失败

相对“最像的四个邻居”并不等于“真的属于同一个物体”：

- 没有绝对相似度下限；
- 没有可靠的跨视角身份；
- 一个区域即使所有边都很差，也总能选出相对最好的四条；
- 连通分量得到数万个小碎片，而不是完整对象。

V6 明确否定的是这套“互选前四邻居就等于对象”的图结构：它不能形成完整对象。至于晚分类造成了多少额外损失，当时的贡献映射错误使这部分不能被干净归因。V6 没有进入融合和类别先验比较。

## 15. 按老师建议做的高斯对象精度审计

### 15.1 为什么这一步很重要

老师提醒：

> “主要是准确率，不是召回率。”
> “看它切出来的物体高斯点，可视化看看。”

之前很多诊断从真实物体出发问“有没有被覆盖”。这一轮反过来，从预测对象出发问：

> 系统说这一堆高斯是一个杯子，这堆高斯到底有多少真的属于同一个杯子？

### 15.2 怎么评估

把每个预测高斯映射到 5 厘米内最近的真实点，分成：

- 正确类别、正确实例；
- 类别正确但实例错误；
- 类别错误；
- 5 厘米内没有真实支持。

未映射高斯必须计为假阳性，不能从分母里悄悄删掉。

### 15.3 可视化怎么看

每个对象导出三维点云，颜色含义：

- 绿色：正确实例；
- 黄色：类别对但实例错；
- 红色：类别错；
- 灰色：没有真实支持；
- 蓝色：对应的真实点。

如果一个预测对象大部分是绿色，说明纯度较高；大量灰色说明扩张到没有真实支持的区域；大量红色说明类别污染；一块真实物体被多个预测颜色切开，说明过分割。

### 15.4 两场景结论

B1 相对 B0：

- AP25 提高 `0.01538`；
- AP50 不变；
- 严格平均精度不变；
- 高斯微平均精确率只提高 `0.000368`；
- 平均召回还略降。

它把前面抽象的指标变成了很直观的事实：

> B1 的主要收益是多碰到一些真实小物体，而不是把对象边界和高斯纯度做得更准确。

审计材料见[高斯对象精度报告](../artifacts/gaussian-object-audit-e62de15/ROOT_CAUSE_REPORT.md)。

## 16. V7：修正最大贡献高斯，并显式做跨视角对象跟踪

### 16.1 底层贡献映射错误

三维高斯是半透明叠加的。一个像素中，第一个高斯贡献后，后面的光还要乘剩余透射率。

正确的当前高斯贡献应是：

```text
当前透明度 × 当前高斯出现之前剩余的透射率
```

也就是 `alpha × T_prev`。

历史代码在更新透射率后再比较，等价于 `alpha × T_new`。此外：

- 空像素的高斯编号初始化为 0；
- 没有同时检查贡献权重是否大于 0。

这会让二维掩码错误地投给三维高斯。问题至少从 `source/v2` 已存在，不是老师 a800 分支或后来实验新增的。

### 16.2 V7 的对象跟踪

V7 不再把单帧结果直接当最终对象：

1. 每张图的掩码提升成一个三维“单帧碎片”；
2. 碎片分成较可靠核心点和完整点；
3. 不同视角碎片如果共享足够核心点，就归到同一对象轨迹；
4. 多视角共同支持的点成为最终核心；
5. 类别在对象形成后才投票；
6. 类别先验原计划只在冻结对象库后改变接纳分数。

### 16.3 实际结果

两场景：

- 在 V7 固定的这两个场景里，修贡献前后的 B1 最终标签逐点相同；
- 这只说明后续步骤把底层差异覆盖掉，不代表底层错误不存在；
- 修正后的 L0 历史十门槛严格平均精度 `0.0544444`；
- AP50 `0.1833333`；
- 高斯微平均精确率 `0.238188`；
- 匹配真实实例召回 `0.621284`。

去掉全场 K 近邻、只保留核心、再加局部补全，都没有达到预先规定的精度与召回联合门槛。因此在这两个场景上，不能单独确认“全场 K 近邻”或“中心吸附”是哪一个主要因果源。

V7 对象库：

- 共 56 个候选；
- 同类别 IoU≥0.25 只有 1 个；
- IoU≥0.50 为 0；
- 极小/小物体 Recall@0.25 为 `0.047619`。

### 16.4 排除了什么

真实点映射到高斯的比例：

- 5 厘米：`98.56%`；
- 10 厘米：`99.94%`。

所以不是坐标完全错了，也不是 5 厘米半径太小。

即使假设能完美删除假阳性，现有碎片支持也只有 2/38 个真实实例能达到 IoU 0.50。候选常呈现：

> 局部非常准，但只覆盖物体的一小块。

### 16.5 后来发现的 V7 实验问题

- 原关联上界混入了语义，不是纯几何；
- 无条件合并碎片，不保证上界单调改善；
- 共识核心错误使用了完整点集合；
- 冲突按碎片次数累计，而不是按物理视角累计。

修正纯几何上界后仍然没有 IoU≥0.50，因此 V7 停止方向成立，但原解释过程不够严谨。

### 16.6 正确结论

V7 证明：在当时冻结的 Grounded-SAM、每像素单赢家提升、碎片规则和两个场景上，候选支持不足。这个结论不应外推成所有 Grounded-SAM 加单赢家的构造都必然失败。类别先验没有运行。

## 17. V8：二维掩码来源 × 高斯贡献方式

### 17.1 要区分哪两个根因

V7 的碎片不完整，可能有两种原因：

1. Grounded-SAM 本来就只切到物体局部；
2. 一个像素只保留一个高斯，丢了半透明叠加中其他真实贡献。

V8 做了一个两乘二实验：

| 掩码 | 单赢家高斯 | 全部透明度贡献 |
|---|---|---|
| Grounded-SAM | G-M1 | G-AM |
| SAM 全部分割 | S-M1 | S-AM |

其中：

- M1 是修正后的最大贡献高斯；
- AM 是把所有实际贡献高斯的透明度质量都累计起来。

### 17.2 两场景几何上限

S-AM 最好：

- 两场景几何贪心上界有 16 个 IoU≥0.50 匹配；
- 说明现有三维高斯、SAM 全部分割和透明度质量提升，**确实包含足够的完整几何支持**。

这是一个重要转折：问题不再主要是“输入里根本没有物体”，而是“自动系统没有把这些片段正确组成对象”。

### 17.3 八场景自动对象库

- 几何 IoU≥0.50 候选只有 2 个；
- 同类别 IoU≥0.50 为 0；
- 统一条件严格平均精度为 0；
- 极小/小物体 Recall@0.25 为 0；
- 精确率和无支持比例都比 B1-fixed 更差。

### 17.4 一个重要的设计自纠错

结果产生前的静态审查发现，V8 对象库根本不读取实例特征。因此：

> “如果 V8 对象库失败，就把 2k 实例特征训练到 10k，看对象库是否改善”

在数学上不可能有效，因为对象库没用这个输入。该分支在看结果前撤销，避免把混杂结果当因果证据。

### 17.5 正确结论

V8 证明：

- S-AM 输入上界够；
- 顺序式掩码重叠跟踪没能把片段正确组成对象；
- 类别先验仍未运行。

- 结果与真实标注准确；
- 通用场景有效；
- 类别先验显著。

### 18.4 我们自己造成的两次误判

#### 误判一：把运行器错误当老师基线失败

首次闭环运行器人为加了 `--iterations 1`，触发历史命令行参数解析缺陷。这个失败不是老师原始命令的真实表现，已撤销。

#### 误判二：比较器把 31 点差异放大成 370,226 点

`scene0025_01/B1` 的两份原始标签在 1,459,291 个点上逐点完全一致。只是其中一份多声明一个 31 高斯的椅子实例。

旧比较器按全局实例排名重新编号。插入一个小实例后，后面所有编号一起平移，于是它误报：

- 差异 370,226 点；
- 变化率 25.37%。

真实导出差异只有：

- 31 点；
- `0.002124%`。

这说明我们必须区分：

- 原始内部分组；
- 真正对外声明的实例；
- 实例类别、分数和包围盒元数据。

### 18.5 原基线仍然存在的真实问题

纠正误判不等于原基线没问题。真正确认的问题包括：

1. **背景可能被当成实例。**
   `-1` 本应永远表示背景，但最终二维投票也会给背景投票。32 份输出中有 14 份包含负编号实例元数据。

2. **大量孤儿标签。**
   高斯标签里有非负实例编号，但实例表里没有对应声明。32 份输出中，孤儿高斯比例为 `26.683%–68.067%`，平均 `42.299%`。

3. **两套真相。**
   `point_labels` 说一套，`instances` 元数据又说一套；如果官方评估、可视化和精度审计这些消费者没有统一按“已经声明的实例”投影，就可能读到不同世界。

4. **最大贡献高斯错误。**
   `alpha × T_new` 和空像素编号 0 是真实底层错误。修复在 `scene0025` 改变 B0 的 `9.802%`、B1 的 `5.403%` 高斯标签，另两个场景不变，说明它是场景相关问题。

5. **小物分支后续不受保护。**
   合并后仍经过全场 256 近邻、统一 10 点过滤和最终类别投票。

6. **没有原生实例置信分数。**
   输出主要只有类别和包围盒。官方平均精度需要按置信度排序，但旧系统只能用统一分数或后补投票比例，说明它不是成熟检测头。

### 18.6 法证闭环后的判断

老师给的仓库：

- 不是“完全跑错”；
- 也不是“已经健康，只是类别先验没效果”；
- 它是能跑的研究原型，但被改造成自动闭集任务后缺少成熟对象身份、输出合同和评分头。

## 19. V9：10k 双源特征和 Clean ObjectBank

### 19.1 为什么提出

V8 已经证明 S-AM 片段里有足够几何支持，但对象关联失败。V9 同时做三件事：

1. 修正法证、比较器和唯一输出合同；
2. 直接训练隔离的 10k 双源特征；
3. 尝试多种对象关联结构。

### 19.2 什么叫双源特征

以前实例和语义监督容易混在一起。V9 明确分开：

- SAM 全部分割只监督“哪些点属于同一对象”的实例特征；
- Grounded-SAM 32 类标签只监督语义特征；
- 固定已有 30k 三维高斯，不重训场景几何；
- 输出到独立目录，不覆盖旧资产。

### 19.3 比较了四种关联

- A0：V8 的顺序重叠；
- A1：全局受约束重叠；
- A2：A1 加 10k 实例特征桥接；
- A3：物理邻域中的互选实例特征图。

理论上，它们都应该把不同视角的单帧碎片组成对象。

### 19.4 实际结果

- 两场 10k 双源特征完成；
- 两场 S-AM 提升完成；
- A0 到 A3 全部完成；
- 几何上界有 `16/38` 个真实实例可达 IoU≥0.50；
- 极小/小物体 Recall@0.25 上界为 `0.954545`；
- 但 A0–A3 最终对象库的几何 IoU≥0.50 全部为 0；
- 类别先验没有运行。

### 19.5 当时看起来像“身份特征失败”

运行记录的关联边精确率约为：

- A0：`0.0506`；
- A1：`0.0637`；
- A2：`0.0636`；
- A3：`0.0615`。

当时很容易得出：

> 10k 实例特征还是区分不了跨视角对象。

但后来发现这个归因过早。

### 19.6 V9 真正的实现错误

1. **至少 A0、A2 的关联日志记录了组件代理边，不是真正被接受的原始碎片边。**
   因此四个条件当时记录的 5%–6% 不能组成一张干净、可以横向比较的真实身份精确率表。

2. **最终对象丢弃了成员碎片的完整点。**
   最后只保留共识核心和全场补点。一个两个视角都正确支持的 100 点对象，可能退化成 3 个核心点。

3. **包含式重叠分数偏爱小碎片。**
   一个 3 点碎片完全落在 100 点物体内，会得到满分关联，尽管它只覆盖了物体 3%。

4. **全局连通会放大一条坏边。**
   A 和 B 误连、B 和 C 又误连，系统会传递地把 A、B、C 全合在一起。

### 19.7 运行器故障与方法结论要分开

首个 A0 实现使用了过大的稠密冲突结构，触及 90 GiB 内存上限并被系统杀死。后来改成严格等价的稀疏实现并恢复完成。

这是工程复杂度故障，不是算法效果结论。

### 19.8 V9 的正确结论

撤销：

> “10k 跨视角身份表示已经被证明不足。”

保留：

> “V9 的具体关联和证据重建实现失败。”

V9 没有测试类别先验。

## 20. V10：证据保真的多视角共识

### 20.1 为什么不是继续调参数

V9 的输入上界高、最终对象却为零，且中间主动丢了完整点。这时继续调类别尺寸或 HDBSCAN 没有意义。V10 先回答：

- 哪一步把完整证据丢了；
- 哪条关联边是真的；
- 小碎片是否被错误打成满分；
- 弱边是否通过传递性合并整个对象。

### 20.2 八级证据漏斗

V10 分别保存：

1. 单帧碎片完整点；
2. 单帧碎片核心点；
3. 组件的完整点并集；
4. 组件的核心点并集；
5. 冲突处理前共识；
6. 冲突处理后共识；
7. 高斯唯一归属后对象；
8. 最终候选。

这样可以明确说“对象在第几步从 100 点变成 3 点”，而不是只看到最终为零。

### 20.3 配对和重建两因素

先在两场景运行四种组合：

| 因素 | 旧方式 | 新方式 |
|---|---|---|
| 碎片配对 | P0：包含式分数 | P1：双向可见覆盖 |
| 对象重建 | R0：核心加全场补点 | R1：只从成员碎片完整点并集重建 |

双向覆盖要求：

- A 的多少证据被 B 覆盖；
- B 的多少证据被 A 覆盖；
- 两个方向都不能太低。

因此“3 点包含在 100 点里”不再得到满分。

### 20.4 最终多视角共识

V10 的正式关联按下面顺序：

1. 先找哪些相机视角真正看到了相似区域；
2. 每对共视图做一对一最佳匹配；
3. 双方必须互为最佳；
4. 第一名要明显领先第二名；
5. 很强的双视角证据可直接成轨迹；
6. 较弱边必须得到第三个视角组成一致循环；
7. 同一帧的层级掩码视为替代假设，不互相当负证据；
8. 一条弱边不能桥接两个已经存在的对象；
9. 类别仍在对象冻结后才确定。

一对一匹配使用匈牙利算法。这个名字来自经典组合优化方法，作用只是：

> 在一张图的多个碎片和另一张图的多个碎片之间，找一组总分最高、且每个碎片最多匹配一次的配对。

### 20.5 什么时候才允许测试类别先验

两场景对象库必须先达到：

- 至少 6 个几何 IoU≥0.50 候选；
- 候选精确率@0.25 至少 10%；
- 有效极小/小物体 Recall@0.25 至少 0.20；
- 可判断关联边的精确率至少 50%。

8 场景还要通过更严格的对象数量、类别、精度、召回、平均精度、实例数量和分数相关性门槛。

只有通过后，才在**完全相同的对象库**上运行统一统计和类别统计的 2³ 比较。类别先验只能改变候选分数、是否接纳和重叠所有权，不能重建对象。

### 20.6 当前状态

V10 后来完成了两场景云端结构验证，并按预注册门槛停止：几何 IoU≥0.50 匹配为 0（门槛 6），候选精确率@0.25 约为 0.0573%（门槛 10%），有效 tiny/small Recall@0.25 约为 0.0455（门槛 0.20），候选数则从 P0R0 的 107 膨胀到 1,745。可判断关联边的精确率约为 0.9285，说明局部边本身不差，但边的组合、对象重建或评价投影仍有严重问题。

随后静态复核发现 V10 的候选评价把未被 GT 点唯一选中的高斯各自变成假阳性哨兵，使高斯远多于 GT 点时产生结构性误罚。这个错误后来通过“三个空间分开评价”纠正：正式 AP 只在 GT 点域计算，Gaussian→GT 用最近 GT 点衡量精度，GT→Gaussian 单独衡量覆盖。因此，V10 的极低数值不能直接作为“应该训练身份头”的充分证据。

V10B 没有启动，类别先验也没有运行。研究随后转向更贴近老师原问题的提示式最小机理实验，以及不依赖旧点级聚类的完整掩码干净基线。后续实际结果见第 25 节。

## 21. 不要把所有“失败”混成一类

历史上最大的沟通问题，是一句“实验失败了”可能代表四种完全不同的事情。

### 21.1 第一类：较可信的具体映射负结果

这类实验满足：

- 绝对指标至少没有像 B2 或 class-first 那样崩塌；
- 统一组和数据组结构相同；
- 参数确实改变了结果；
- 跑了足够场景；
- 没有发现会专门破坏这组统一/数据对照的评估实现错误。

最接近这一标准的是 `prior-v2`：

- 调试集有小幅正信号；
- 多种子后变弱；
- 48 场景方向反转；
- 当前尺寸/平滑/小物体映射没有稳定价值。

teacher-prior 得到的是较干净但没有达到门槛的微弱正差 `+0.000128`，因此实验层面的结论仍是负结果或证据不足。这里比较的是 a800 原顺序下“SAGA20 全类别共享参数”与“逐类参数”，不是老师最初只处理 8 个小类的 B1。

### 21.2 第二类：主干先坏了

例如：

- B2 的统一主干从约 0.055 掉到 0.020；
- class-first 的统一主干只有 0.000208；
- V3 多锚点保护把实例数翻倍，严格平均精度腰斩；
- V8 统一对象库平均精度为 0。

在这种情况下，数据条件相对统一条件略好也没有方法意义。好比两辆车都掉进沟里，一辆比另一辆多前进半米，不能说明发动机设计成功。

### 21.3 第三类：在类别先验之前早停

V5、V6、V7、V8、V9 都属于：

- 先检查候选或对象库；
- 没达到健康门槛；
- 按预注册规则不运行类别先验。

它们否定的是各自的候选生成、关联或重建方案，不是类别先验。

### 21.4 第四类：工程或评价错误

包括：

- 运行器误传 `--iterations 1`；
- 比较器把 31 点差异放大成 370,226 点；
- 最大贡献高斯用错透射率；
- 空像素错误指向高斯 0；
- V7 上界混入语义；
- V9 至少在 A0/A2 中记录了组件代理边；
- V9 丢弃碎片完整点；
- 稠密冲突结构触发 90 GiB 内存杀死。

这些问题需要修复和重算，不能直接拿来支持科学结论。

### 21.5 一张表看清证据性质

| 路线 | 被否定的具体东西 | 是否真的比较了类别先验 |
|---|---|---|
| B2 | 复杂覆盖式先验主干 | 是，但比较骨架已退化 |
| class-first | 硬语义优先主干 | 是，但主干几乎归零 |

| 干净完整掩码基线 | 当前自动跨视角共识和对象重建 | 否，类别先验未进入 |
| 平面掩码与晚期过滤 | “重叠掩码”或“最后过滤”是唯一主因 | 否，均是无先验根因审计 |

## 22. 目前最可信的结构性根因树

下面按数据流从前到后排列。前一层坏了，后一层通常无法补救。

### 22.1 输入层：二维掩码和类别标签

**已经证实：**

- Grounded-SAM 对极小/小实例覆盖很低，V3 中约为 17.97%/27.08%；
- 降低检测阈值可以把中位覆盖从约 16.9% 提到 26.0%，但会产生更多碎片；
- SAM 全部分割能显著提高几何支持。

**通俗解释：**

如果每张照片只框到杯子把手，三维后处理很难凭空补出杯身。

### 22.2 二维到三维提升层

**已经证实：**

- 历史最大贡献高斯公式错误；
- 空像素错误指向第 0 个高斯；
- 每像素只保留一个赢家，在机制上会丢失半透明叠加中的其他真实贡献；
- S-AM 组合相对 V7 的 Grounded-SAM 加单赢家显著提高了几何上限，但当前汇总不能把提升份额单独归给“换成 SAM 全部分割”或“累计全部透明度质量”中的某一个因素。

**通俗解释：**

二维老师已经圈对了区域，但把作业发给了错误的三维学生，或者只发给一个学生、漏掉其他真正参与画面的学生。

### 22.3 单帧碎片层

**已经证实：**

- 好碎片常常局部精确率高，但覆盖率低；
- 核心点适合做高置信起点，但不能直接当完整实例；
- 同一帧 SAM 层级掩码常是多个替代假设，不能当成多个独立视角相互否定。

### 22.4 跨视角对象身份层

**已经证实：**

- 原始 a800 没有持续的跨视角对象编号；
- V6 局部图形成数万个碎片；
- V7 顺序核心重叠和 V8 顺序掩码重叠没有组成健康对象；
- V9 包含式分数会给 3 点对 100 点满分；
- 单条假边通过连通分量可合并整个错误链。

**后续补充结果：**

- V10 的局部可判断关联边精确率很高，但全局组合产生候选爆炸，未形成可用对象；旧候选评价定义又存在结构性误罚，所以没有启动身份头训练；
- 完整掩码干净基线的几何上界很高，自动多视角共识却接近零，进一步把主要矛盾定位在关联、组件形成和对象重建，而不是“输入里完全没有物体”；
- 平面唯一掩码降低污染但没有增加完整对象，说明同帧层级歧义不是唯一根因。

是否训练专门的跨视角身份特征，已经是需要单独授权的新研究方向，不是当前类别先验实验的默认下一步。

### 22.5 对象重建层

**已经证实：**

- V9 丢弃成员碎片的完整点是严重错误；
- 只保留核心加全场补点会同时造成漏召回和错误扩张；
- 重建必须保住成员碎片的完整证据，并让模糊点保持背景。

### 22.6 语义分类层

**已经证实：**

- 过早的硬类别切分会传播错误；
- 只在 SAGA20 内竞争时，墙、地板等非目标区域会被强行塞给某个目标类；
- 原分支类别最后还能被二维投票改写；
- 语义应该在对象形成后决定，而不是主导对象关联。

### 22.7 全场后处理层

**有直接代码证据和强结果证据：**

- 全点向少量聚类中心吸附容易跨边界扩张；
- 全场 256 近邻会让小物体被大邻域多数吞掉，也可能把错误标签扩散出去；
- 统一 10 点过滤可能再次删除小物体；
- 但冻结真候选重放中，原 256 近邻曾把 4 个候选平均 IoU 从 0.5222 提高到 0.6340，保护旁路反而没有改善；
- 8 场只有 3 个分支实例在近邻后进入 3–9 点过滤区间，且都不是真候选，所以 `filter10` 不是主要损失点；
- 晚期 2×2 中全面放宽检测过滤和整实例剪枝只能把 IoU≥0.50 从 1 提到 3，并将候选数增至 190、precision@0.25 降到 7.37%。

因此不能把近邻或晚期过滤简单写成“吞小物体的唯一根因”；它们既可能补全，也可能污染，主要实例缺失发生在更早的组件形成阶段。

### 22.8 输出和评估层

**已经证实：**

- 背景可能被写成实例；
- 32 份输出中平均约 42.299% 非负高斯标签没有实例元数据；
- 原始标签和实例表是两套真相；
- 旧系统没有可靠原生实例分数；
- 旧比较器存在编号平移假阳性；
- 只看真实点到高斯会低估高斯侧污染；
- 历史上曾把正式 GT 点域 IoU、Gaussian→GT 精度和 GT→Gaussian 覆盖混成一个伪指标，现已拆为三个独立评价空间；
- 完整证据覆盖上界允许 GT 完美删假阳性和跨对象复用，不能再称为自动实例上界。

### 22.9 类别统计映射层

**已经证实的负结果：**

- prior-v2 的尺寸/平滑/小物体映射没有稳定泛化；
- teacher-prior 的当前公式虽然生效，但只产生约 +0.000128；
- 类别尺度在 V4 几乎没有改变候选匹配；
- 类别核心支持更像删候选：精确率略升、召回下降；
- 已知对象和类别的提示式最小实验中，“完整物体典型尺寸→当前原生尺度门”场景等权差约为 -0.0000474，九点网格能力上界也只有 +0.003673；
- 10k 同轨迹正控没有增加尺度门容量；
- 旧 5 厘米平滑项在当前候选域大量饱和，旧单边尺寸会拒绝完整正候选。

**尚未回答：**

- 当对象候选已经完整、干净时，类别尺寸、支持度和平滑度能否帮助候选评分和重叠所有权；
- 类别先验是否只对物理小实例有效，而不提高全体类别平均精度；
- 支持量、边界平滑和网格统计如何与三维高斯密度域进行无泄漏、同量纲映射。

## 23. 到底是老师基线有问题，还是我们做坏了

答案不是二选一，而是两边都发生过。

### 23.1 老师基线本身的真实问题

- 它是工程研究原型，不是成熟的自动实例检测器；
- 没有持续跨视角身份；
- 小类分支之后仍受统一后处理；
- 最大贡献高斯公式和空像素编号有错误；
- 输出合同有背景实例、孤儿标签和无原生分数；
- 统一参数只是一种早期小物体试验。

### 23.2 我们自己做错或误判的地方

- B2 把太多结构变化和参数变化绑在一起；
- class-first 把语义硬切分放得过早；
- 一度把最终 48 场景“看过”当成必须重选重训，过度强调盲测洁癖；
- 一度用错误比较器误报 25.37% 差异；
- 一度把运行器的 `--iterations 1` 错误归给老师基线；
- V7 上界定义不纯；
- V8 曾设计一个对象库根本不读取的 10k 正控，幸好在出结果前撤销；
- V9 至少在 A0/A2 中评价了组件代理边，而且最终重建丢弃完整点，却差点误判为身份特征不足。

### 23.3 为什么这些纠错不是“白做”

科学研究的价值不只来自最后正结果。经过纠错，我们现在知道：

- 哪些数字是可靠的；
- 哪些相对提升只是坏主干里的补偿；
- 哪些停止发生在先验之前；
- 哪些错误来自工程；
- 下一轮必须保住哪些证据。

比起继续盲调尺寸或最小簇，这些结论大幅缩小了真正问题。

## 24. 类别先验究竟被证伪了吗

### 24.1 对“所有类别先验都没用”的回答

**没有被证伪。**

原因是：

- 老师提出的是一个很宽的研究假设；
- 大多数后期实验没有形成健康对象库，先验没运行；
- 早期一些正差发生在坏主干，不能证明有效；
- 早期一些负差只覆盖具体统计和公式，不能外推所有类别知识。

### 24.2 对“我们当前三种数据统计映射有用吗”的回答

**现有证据偏负面。**

尤其是 prior-v2：

- 绝对指标与 B0/B1 同一数量级，但旧主干并非因此被证明完全健康；
- 同结构比较；
- 调试集小幅正；
- 多种子变弱；
- 48 场景转负。

所以如果问题限定为：

> “把当前 ScanNet 训练统计按 prior-v2 公式映射到尺寸、平滑、小物体参数，是否稳定提高严格平均精度？”

答案是：

> **没有发现稳定改进。**

### 24.3 对“老师的小物体思路有价值吗”的回答

**有弱证据，但远未达到显著结论。**

- AP25 和 AP50 有提升；
- 个别小物实例被救回；
- 严格平均精度弱且不稳定；
- 同时会增加纯假阳性。

正确表述是：

> 老师的小物体特殊化方向有可观察信号，但早期分支没有足够候选质量控制，不能证明稳定收益。

### 24.4 当前最公平的终局问题

真正还没完成的是：

> 在一个经过验证、完整、干净、冻结的三维对象库上，只把全局统计换成逐类训练统计，类别先验能否稳定提高严格平均精度或小物体指标？

但是提示式最小机理已经补上了一条重要的直接证据：当对象身份和类别已知、正提示完全相同，只把全局典型包围盒尺寸换成逐类典型尺寸时，当前 SAGA 原生尺度门没有得到稳定收益。这个结论明显缩小了“类别先验仍可能有效”的范围：不能再把希望主要寄托在当前尺寸门或继续训练它；如果仍要检验先验，更合理的接口是约束健康对象图中的错误合并、合理支持量或保留决策。

问题在于，自动对象主干到目前仍未达到健康门槛。继续重构主干已经成为一个独立研究项目。因此，当前最公平的终局问题还应加上一个课题管理前提：导师是否愿意把“建立健康自动实例基线”明确列为后续工作，而不是默认它只是类别先验实验的一小步。

## 25. V10 之后到底又做了什么

这一节补齐初稿之后的全部关键探索。它不是把每个提交都列一遍，而是按因果问题说明为什么做、得到什么、结论边界在哪里。

### 25.1 提示式最小尺寸机理：把问题缩回老师原意

我们意识到 V5–V10 同时解决自动提案、跨视角身份、对象补全、分类和评分，已经离老师的简单想法太远。于是停止扩建对象库，改做最小实验：对象身份和类别都已知，正提示完全相同，只把全局典型尺寸换成逐类典型尺寸，通过 SAGA 原生 scale gate 影响同一个提示分割。

8 个物理场景、124 个对象的配对实验中，122/124 个 gate 向量和 119/124 个布尔掩码发生了真实变化，说明先验机械介入了输出。可是场景等权的 `D-class − U-global` IoU 只有 `-0.0000474341`，95% 区间为 `[-0.00106548,+0.00063856]`；Gaussian 精度差为 `-0.0003428140`。这个结果距离预注册的 `+0.02` 实用门槛超过两个数量级。

为了区分“类别统计映射错了”和“尺度门本身没有能力”，又运行固定九点尺度网格的理想选择上界。场景等权 `GridOracle−U` 只有 `+0.00367325`，0/8 场景达到 `+0.01`，仅 4/124 对象达到 `+0.02`。按历史原生可见掩码尺度构造的对象正控也只有 `-0.00015527`。结论是：当前 2k 特征的尺度门能扰动边界，却没有广泛、稳定、实用的尺度可控性。

### 25.2 10k 尺度容量正控：不是训练轮数不够

随后在 `scene0591_02` 和 `scene0645_00` 的 34 个固定对象上，沿同一训练轨迹比较原生预算与 10k 检查点。10k 的网格上界只有 `+0.00071346`，反而低于原生预算的 `+0.00241653`；0/34 对象达到 `+0.02`。因此停止继续 20k 或增加尺度网格。这个结果否定的是“多训练到 10k 就能修好当前尺度门”，不是所有 10k 特征训练。

### 25.3 最终小簇删除审计：小物并不是主要死在最后一步

针对“老师本意可能是让小物候选穿过降噪，不被最后小簇过滤删掉”的质疑，我们冻结 8 场候选，只审计近邻之后、`filter10` 之前的 3–9 点分支实例。258 个分支候选中只有 3 个落入这个点数范围：一个 3 点插座、一个 6 点手机、另一个 3 点插座，三者同类 IoU 都为 0；类别规则只会额外保留 6 点手机，但它没有可评价 GT 支持。

所以最后统一 10 点过滤不是主要丢失点。真正的小物体在更早的语义筛选、聚类、全点分配或近邻阶段就没有形成可用候选。这个审计避免了继续给最后过滤器加保护旁路。

### 25.4 全类别类别化降噪：结构修正真实进入了，但候选池不健康

为了更忠实实现老师“全类别参数参与降噪”的想法，我们让 SAGA20 全部类别进入公共候选结构，在同一个候选池上比较全局尺寸、平滑、支持量与逐类统计，并让接纳的小簇在近邻和过滤前受到保护。DEV8 冻结得到 1,344 个候选，但同类 IoU≥0.25/0.50 的只有 15/4 个，候选精确率@0.25 只有 1.116%，tiny/small Recall@0.25 只有 10.13%。

逐类参数不是没生效：808 个候选的分数改变，1,258 个候选的支持门槛改变。问题是 U 的最高分约 `3.51e-6`，D 的最高分约 `0.002253`，都远低于接纳阈值 `0.20`，所以 U/D 最终都没有接纳候选，输出相同。进一步检查发现 5 厘米平滑项大量饱和在 `exp(-12.5)`，类别尺寸项又拒绝了全部 15 个正候选；公共证据 Q 与 IoU 的相关为 `+0.225`，加入旧先验后降到 `-0.125`。

这轮不能写“逐类参数无效”，因为候选池本身几乎没有真对象，且公式会把所有分数压到零附近。它能说明的是：旧尺寸、平滑和支持映射不适合这个候选域。

### 25.5 三分诊断：候选形成是首要问题，绕过近邻没有得到支持

为了把“候选形成差”“全场近邻吞候选”“先验域本身无信号”分开，我们做了 E1、E2、E3 三项只读诊断。E1 显示 124 个 GT 对象中只有 28 个进入语义可达集合，采样 HDBSCAN 只恢复 2 个 IoU≥0.25 对象，完整分配后才到 15 个；515/1,344 个候选，也就是 38.3%，出现原始 HDBSCAN 成员不属于最终 full 候选。

E2 只取 4 个 IoU≥0.50 真候选，重放原近邻和保护旁路。原近邻保留了四者，并将平均 IoU 从 `0.5222` 提高到 `0.6340`；保护旁路停在 `0.5222`。因此没有证据支持“一律绕开全场近邻”。

E3 用完整对象、截断碎片和错误合并做先验能力正控。类别尺寸能够区分完整对象和错误合并对象，说明先验域存在一定信号；但旧单边尺寸无法识别过小碎片，平滑项仍然饱和。这也是为什么不能把当前负结果外推成所有类别知识无效。

### 25.6 候选形成追踪：HDBSCAN 重分配有错，但不是唯一根因

下一步逐点记录采样顺序、HDBSCAN 原始簇、membership、阈值前分配和完整候选。DEV8 只有 7/124 个 GT 达到可诊断的语义覆盖，其中 6 个在原始聚类阶段已经失败，只有 1 个健康。局部同实例与异实例的 affinity 边 AUROC 均值为 `0.84515`，oracle-seed Recall@0.25 为 `0.57143`，所以没有触发“2k 表示必然不足”的 10k 正控。

修复完整分配的 C1 将候选精确率提高 43.92%，却减少了 IoU≥0.50 匹配，并使一个 GT 的最佳 IoU 下降 `0.06893`，超过允许的 0.05；C2 则让精确率下降 60.46%，候选数超过 1.25 倍。结论是：原始成员被跨簇重分配确实不合理，但多数对象在此之前就没有形成好原始簇，事后修包络不够。

### 25.7 修 HDBSCAN 输入和换图聚类：都没有恢复实例

两场景中，历史 R0 有 374 个候选，IoU≥0.25/0.50 为 7/1。使用纠正距离的 R1 只剩 3 个 IoU≥0.25 匹配；锚定原成员的 R2 产生 5,016 个碎片，只得到 3 个 IoU≥0.25；物理近邻与 affinity 互选图 G1 产生 58,473 个组件，IoU≥0.25 为 0。

这组结果把根因说得更清楚：HDBSCAN 输入、原成员重分配和全局中心扩张都有问题，但“换一个更正确的聚类器”也不能自动得到物体身份。同一物体的局部特征和可见碎片没有形成足够连通、稳定的对象单位。

### 25.8 表示版本与语义路由：类别分错只是第一层损失

两场景 2×2 对照比较原生 2k 与 V9 10k 表示、预测类别与 GT 类别。原生 2k 加预测类别得到 5,033 个候选，IoU≥0.25/0.50 都为 0；换成 GT 类别后为 2/1。V9 10k 加预测类别为 1/0，换 GT 类别仍为 1/0。

这说明语义路由错误真实存在：预测类别会在聚类前删掉属于对象的高斯。但即使离线给出正确类别，当前 affinity 和原始实例形成也只能恢复极少对象。语义回答“这是椅子”，物体身份回答“这是第几把椅子”；前者正确不能替代后者。

### 25.9 完整掩码干净基线：输入有上界，自动关联没把它变成对象

我们最后彻底绕开旧 HDBSCAN、中心吸附和全场近邻，直接把每一帧的完整 SAM 掩码当成一个对象观察，用正确的 `alpha × T_prev` 提升到高斯，再按多视角共识关联。两场景的离线几何上界有 36 个 IoU≥0.50 对象，21/21 个 tiny/small GT 在 IoU≥0.25 可达；DEV8 上界有 100 个 IoU≥0.50 对象，75/79 个 tiny/small GT 可达。

但自动共识基线失败：DEV8 的 C0 有 554 个候选、U 有 134 个，二者都没有 IoU≥0.25 候选，严格 mAP/AP50 为 0。输出合同没有 orphan、负 metadata 或重复所有权，说明不是导出格式把 AP 清零。输入里有完整支持，自动跨视角关联和对象重建却没有把它们组成实例。

曾设计过一条“类别先验参与 raw 碎片图组装”的路线，并通过本地测试，但没有取得云端方法结果，后来被完整掩码干净基线取代。它不能算入实验证据。

### 25.10 评价纠正和平面化掩码：准确率提高，完整性没有恢复

干净基线复核把三种空间完全分开：正式 AP 在 GT 点域计算，Gaussian→GT 衡量预测精度，GT→Gaussian 衡量覆盖。GT-as-prediction、官方九档 AP、历史十档 AP、冻结输出重建都通过。一次 PLY 身份告警后来确认是评价器读取错误字段，不是资产漂移。

同一次 SAM 生成同时派生分层掩码 H′ 和像素唯一的平面掩码 P。P 的候选数从 42 降到 20，IoU≥0.25 匹配从 6 降到 5，但 precision 从 14.29% 升到 25%；IoU≥0.50 两边都只有 1 个。tiny/small Recall@0.25 从 14.29% 降到 9.52%，Gaussian 精度从 25.84% 升到 36.47%，污染从 74.16% 降到 63.53%。

因此，平面化确实删掉一批错误支持，却也删掉真支持，没有恢复完整对象。另有一个临界 CUDA 原子归约点造成 P bank 重复运行出现一条稀疏成员差异，最终输出未变，但按硬确定性合同仍记机械失败，不能事后加容差改写为通过。

### 25.11 晚期过滤闭环：不是“对象早已正确，只是最后被删”

阶段漏斗曾显示 accepted components 到检测过滤约删除 97%，所以最后做了一个零 GPU 2×2：是否关闭逐点检测硬过滤，是否关闭晚期整实例剪枝。技术合同全部通过，正式 AP 仍使用冻结分数。

H′ 在晚期过滤前共有 9,765 个可评价组件，但只有 25 个 IoU≥0.25、5 个 IoU≥0.50，后者低于进入新导出器所需的 6 个。当前臂有 42 个候选、6 个 IoU≥0.25、1 个 IoU≥0.50；只关检测过滤后为 56/12/1；只关晚期剪枝为 93/7/1；两者都关为 190/14/3，precision@0.25 下降到 7.37%。P 的最宽松臂也只有 4 个 IoU≥0.50。

所以晚期过滤确实删掉一些有用支持，也能提高宽松小物召回，但它不是主要根因。全面放宽只释放更多碎片和假阳性，无法把上游组件恢复成足够多的完整实例。条件性清洁导出器没有获准实现，DEV8 和类别先验都没有运行。

### 25.12 当前真正需要的不是又一个默认实验，而是范围决策

现有证据支持两个诚实选择。第一，收束课题：报告老师的小物体分支有弱信号，但当前尺寸门、prior-v2 和多种映射没有稳定收益；同时说明一般类别先验没有在健康自动主干上被穷尽检验。第二，明确另立“干净自动实例基线”项目：先用真正对象级二维掩码或经过资产审计的 SAI3D 式几何超点建立健康无先验主干，再测试类别约束。

第二条路线不应被当作类别先验实验的自动下一步。它需要导师确认课题范围、资产条件和时间预算。若没有这项授权，最合理的工作是整理负结果和因果证据，而不是继续增加 V 编号、阈值或对象跟踪器。

## 27. 关键术语速查

| 名词 | 最通俗的解释 |
|---|---|
| 3DGS | 用大量半透明小椭球表示三维场景 |
| 高斯 | 3DGS 里的一个带位置、大小、方向、颜色和透明度的小椭球 |
| 语义分割 | 告诉每个位置是什么类别 |
| 实例分割 | 还要区分同类中的不同个体 |
| 闭集 | 只能从预先给定的类别名单里选 |
| 掩码 | 图像中某个目标的像素区域 |
| 二维到三维提升 | 把二维像素区域对应到三维高斯 |
| 实例特征 | 判断两个高斯是否属于同一个具体对象的向量 |
| 语义特征 | 判断高斯像什么类别的向量 |
| HDBSCAN | 按密度找点簇，并把稀疏点当噪声的聚类算法 |
| K 近邻 | 看附近 K 个点，用多数票平滑标签 |
| 候选 | 可能是一个对象、但尚未正式接纳的一组高斯 |
| 核心点 | 候选里证据最可靠的部分 |
| 外围点 | 围绕核心、可能属于对象但更不确定的部分 |
| 单帧碎片 | 一张图中的掩码提升到三维后得到的局部对象片段 |
| 跨视角轨迹 | 多张图中被认为属于同一物体的碎片集合 |
| 对象库 | 把候选对象及其证据保存起来，供后续分类、评分和先验重放 |
| 几何超点 | 先按空间邻接、表面连续性、颜色或法线把许多相邻点切成稳定小块，再以小块而不是单点做实例合并 |
| 交并比 | 预测和真实区域重合程度 |
| 精确率 | 预测出来的东西有多少是真的 |
| 召回率 | 真实东西有多少被找回来 |
| 假阳性 | 系统说有物体，实际没有或严重错误 |
| 过分割 | 一个真实物体被切成多个预测实例 |
| 合并错误 | 多个真实物体被粘成一个预测实例 |
| 置信区间 | 考虑场景变化后，真实平均差大概可能落在哪个范围 |
| 正控 | 本应改善某个环节的小实验，用来确认瓶颈判断是否正确 |
| 上界实验 | 假设后续选择近乎完美时，当前输入最多能达到多好 |
| 旁路实验 | 只记录候选和诊断，不改写原最终结果 |
