# 2026-09-03 网页审计摘要

## 审计带来的研究收束

网页端审计指出，此前不少实验虽然发现了真实工程问题，但逐步把研究重心从“类别先验是否有用”转向了“重建一条更好的自动实例分割主干”。老师原任务并不要求先把公开 SAGA 改造成完整的新系统；老师交付的 `postprocess.py` 本来就会自动形成全场实例，`other_classes` 只是其中少数小物体的特殊处理雏形。

因此，下一项最有解释力、也最接近原任务的实验是：冻结老师自动流程在全场 KNN 前已经形成的全部临时实例，让 global 和 class 两个条件使用完全相同的候选、二维类别投票与下游处理，只改变所读取的训练集三轴尺寸统计。先比较候选排序；排序没有信号就停止，排序通过才做最小恢复和独立场景复核。

## 仓库核对后的四项纠正

1. 公开 SAGA 是提示式分割来源，不能称为当前自动 ScanNet 实例 AP 基线。实验基线是修正后的老师自动流程 `T1-B1`。
2. 老师交付候选更接近 28 标签、7 个小物类别；当前实验运行 32 标签、8 个小物类别兼容流程，并只在 SAGA20 上正式评价。两者不能混称。
3. 特殊分支写入新标签后没有同步更新旧全局 `point_assignment_confidence`，所以该置信度不能跨来源使用。本轮公共分数只取 KNN 前二维投票赢家比例 `Q`。
4. ScanNet 正式主协议是 IoU 0.50 至 0.90 九档；0.50 至 0.95 十档只能保留为历史对照。候选匹配还必须严格一对一，重复命中同一 GT 的候选计为假阳性。

## 结论边界

本轮只检验逐类米制 PCA 三轴尺寸相对全局尺寸是否有额外价值。固定 5 cm 平滑度和支持量此前都存在量纲、密度或作用位置混杂，不与尺寸同时测试。若 KNN 前候选容量不足，就报告当前自动基线的候选限制；不再以此为由启动新候选系统。若候选充足而 class 尺寸没有改善同池排序，才得到当前尺寸接口的干净负结果。
