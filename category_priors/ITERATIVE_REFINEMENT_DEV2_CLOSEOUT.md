# SAGA 二维至三维闭环精修 DEV2 负结果结案报告

更新日期：2026 年 9 月 6 日  
实验代码：`987cc02e5feabeb9ae52f761a60b76b954dc2fa5`  
实验场景：`scene0645_00`、`scene0025_01`

## 结论

这轮实验可以结束，不应扩到 DEV8。

两场景共得到 57 至 59 个可追踪的精修预测，但没有一个救回 B0 漏检对象。IoU 0.25 和 0.50 下的救回真阳性均为 0。与此同时，官方九档 mAP 从 B0 的 6.05% 降到 4.57%，AP50 从 18.33% 降到 15.00%，AP25 从 22.22% 降到 17.50%。稳健、平衡、覆盖三种局部图配置得到相同的正式指标。

这是整套二维至三维闭环在当前接口上的负结果。它不能回答类别尺寸先验有没有用，因为本轮只运行了 `D-class`，没有运行同结构的 `U-global`。在无先验实例主干尚未健康时，继续比较两种尺寸统计也没有意义。

## 本轮实际做了什么

输入是老师兼容自动流程产生的全 SAGA20 分支候选。每个候选保留两组点：

- `seed_support` 是候选在旧全场近邻处理前的完整成员；
- `seed_anchor` 是这些成员与旧流程后期仍存活实例的交集。

系统将候选投到多个相机视角，在裁图中用 GroundingDINO 重新识别，再用 SAM 分出二维掩码。二维掩码通过两种方式回写到 Gaussian：最大 `alpha*T_prev` 贡献者产生硬证据，全 alpha 贡献产生软覆盖。局部图根据这些证据增删 Gaussian，随后执行合并、拆分、B0 所有权裁决和最终二维类别投票。每个候选最多运行两轮。

三个局部图配置只改变全 alpha 软证据权重和图边平滑强度：

| 配置 | 软证据权重 | 图边权重 |
| --- | ---: | ---: |
| 稳健 | 0.5 | 2.0 |
| 平衡 | 1.0 | 1.0 |
| 覆盖 | 2.0 | 0.5 |

第一场完成后进行了两次只读重放。最终输出、实例、类别和血缘逐字节一致。两场输出均无孤儿标签、负实例 metadata 或重复所有权。Gaussian 到 GT 的 5 厘米映射率分别为 96.84% 和 99.36%。因此，负结果不能用随机漂移、坐标错位或输出合同错误解释。

## 为什么二维复核没有形成正确对象

### 1. 二维复核继承了三维种子的错误范围

GroundingDINO 的候选框必须与种子投影相交，并包含种子中心或高贡献种子点。SAM 的正提示同样来自种子投影。这个设计可以避免模型跑到完全无关的位置，但也让二维模型受到错误三维种子的强约束。

如果 `seed_support` 已经混入地面、墙面或相邻同类物体，裁图和提示会围绕这片污染区域生成。二维模型此时不是独立判断“漏掉的物体在哪里”，而是在回答“这片已有投影附近能分出什么”。候选起点错误时，复核容易确认大背景面或邻近显著物体。

运行记录中确实出现大量分支类别与复核类别不一致的情况，例如候选后来被复核为 `floor`、`wall`、`ceiling`，或者复核类别与最终投票类别不同。这不是单纯的分类问题。它说明用于裁图和回写的二维对象假设经常没有锁定原候选想表示的那个实例。

对应代码：

- 候选和锚点定义：`category_priors/iterative_refinement/seeds.py`；
- 种子投影、竞争区域和裁图：`category_priors/iterative_refinement/pipeline.py:394-402`；
- 二维检测和掩码选择：`category_priors/iterative_refinement/reviewer.py`。

### 2. 回写得到的是可见性支持，不是跨视角物体编号

`alpha*T_prev` 能回答某个像素主要由哪些 Gaussian 贡献。它不能单独回答这些 Gaussian 是否属于同一个物体。两个相邻表面、细小物体与其背景、透明边界和遮挡边缘都可能在像素足迹中混合。

硬证据要求至少两个独立视角支持，这个门槛在代码上生效了，但硬证据相对软证据和局部区域仍然很稀疏：

| 场景与轮次 | 可运行图割的候选 | 硬支持点合计 | 软证据点合计 | 局部区域点数合计 |
| --- | ---: | ---: | ---: | ---: |
| `scene0645_00` 第一轮 | 96 | 2,937 | 392,862 | 1,425,626 |
| `scene0645_00` 第二轮 | 113 | 6,776 | 686,517 | 2,257,297 |
| `scene0025_01` 第一轮 | 120 | 8,569 | 781,976 | 3,359,219 |
| `scene0025_01` 第二轮 | 128 | 17,604 | 1,167,227 | 4,385,390 |

这些数是逐候选求和，同一 Gaussian 可被多个候选重复计入，不能解释成场景中的唯一点数。它们仍揭示了比例关系：少量硬支持在大得多的软证据和局部图中传播。只要二维掩码锁错对象，图割会把错误证据变成空间上连续的错误片段。

证据职责在 `category_priors/iterative_refinement/evidence.py:187-241` 定义。局部图的有限项在 `local_refine.py:339-366` 构造。

### 3. 局部图算得稳定，但优化目标没有代表“正确实例”

性能重构后，局部图不再是计算瓶颈。第一场第一轮图精修约 4 秒，第二轮约 8 秒；第二场分别约 394 秒和 827 秒。三配置共享拓扑，候选级结果可断点恢复。

问题在目标函数。图边只鼓励物理邻近且关联特征相似的 Gaussian 取相同标签，节点项来自锚点、硬证据、软证据和 B0 所有权。这里没有明确的跨视角实例编号。错误的种子或掩码证据也能形成低能量、空间连续的解。

三个配置改变了软证据与平滑的相对强度，却得到完全相同的 AP 和零救回。这说明当前失败不是某一个图权重略微不合适。继续调这两个参数不会补上缺失的实例身份信息。

对应代码：`category_priors/iterative_refinement/local_refine.py:339-419` 和 `local_refine.py:545-655`。

### 4. B0 融合的单次保护挡不住许多错误候选的累计影响

融合器对单个候选设有约束：从 B0 背景领取点需要两视角支持，从已有 B0 实例划点也需要强证据；划走比例过大或导致原实例断连时会回滚。这些检查在 `local_refine.py:752-834`。

但是，水库中有 165 和 209 个相互重叠的候选。保护规则逐候选判断，不能保证许多局部合法修改叠加后仍保持整个场景稳定。结果正是大量原 B0 前景被删除或改归其他碎片，背景中新领回的点却很少。

第二场的融合、合并和导出也远慢于图割：合并拆分约 1,520 秒，投票导出约 871 秒。大量候选和子对象在后段竞争同一批 B0 点，既增加耗时，也放大碎片化。

### 5. 最终类别投票无法修复错误几何

最终输出仍使用统一的 33 路二维投票。它可以给一个已经成形的实例命名，却不能把错误碎片拼回完整物体。若投票赢家不是 SAGA20、置信度不足或背景占优，修改会回滚；若错误碎片恰好得到一个前景类别，它就会作为假实例导出。

两场最终导出的可追踪分支预测共 57 至 59 个，全部是 B0 漏检救回评价中的假阳性。实例数量暴增而 mAP 下降，说明末端投票没有把错误几何过滤干净。

导出和血缘处理位于 `category_priors/iterative_refinement/pipeline.py:937-1010`。

## 失败链条

本轮结果可以概括为：

```text
不健康的三维分支候选
→ 种子约束的二维裁图和提示
→ 二维模型经常锁定背景面或邻近物体
→ alpha 回写把掩码可见性转换成稀疏硬证据和大量软证据
→ 局部图把这些证据扩成连续片段
→ 许多重叠候选反复争夺 B0 原有前景
→ 场景被切成大量小实例
→ 最终类别投票只能命名或回滚，不能恢复正确实例身份
→ 零救回、假阳性增加、原 B0 指标下降
```

二维模型、alpha 回写和局部图并非各自完全失效。它们都执行了设计的计算。失败发生在信息含义没有闭合：系统从一个可能错误的三维片段出发，得到围绕该片段的二维掩码，再把这个掩码写回同一片局部区域。这个循环能强化一致性，却没有可靠机制证明多个视角中观察到的是同一个真实物体。

## 能下什么结论

可以确认：

1. 当前完整闭环没有达到最基本的对象救回目标，DEV8 不应启动。
2. 负结果不是由随机性、坐标错位、孤儿标签或实例编号比较错误造成的。
3. 当前系统主要重组 B0 已有前景，没有从背景中恢复漏检对象。
4. 三种图权重结果相同，继续在这两个权重上微调缺少依据。
5. 局部图性能优化是有效的工程改进，但它只加快了一个科学上无效的接口。

不能确认：

1. 不能说类别尺寸先验无效。本轮没有 `U-global` 对照。
2. 不能说 GroundingDINO 或 SAM 本身不适合任务。当前裁图和提示受污染种子约束。
3. 不能说 alpha 贡献公式错误。融合后端已通过参考校验，问题是贡献证据不足以表达实例身份。
4. 不能把结果外推到所有二维至三维方法。这里只否定当前候选水库、提示方式、回写和 B0 融合的组合。

## 停止决定

按照实验标准，当前不扩 DEV8，不运行 U/D 类别先验比较，不增加第三轮，不调图权重，也不引入新聚类器或新训练。云端产物保留只读。

如果以后重新启动研究，下一步应先做离线阶段漏斗，而不是马上改代码。漏斗至少要回答：

1. 每个种子在裁图前与最近 GT 的几何关系；
2. DINO 框和 SAM 掩码是否覆盖同一个 GT；
3. 硬支持、图割输出和最终实例在哪一级首次偏离该 GT；
4. B0 前景损失由哪些候选累计造成；
5. 若给定正确二维掩码，当前回写和融合能否恢复对象。

第五项是关键正控。如果正确二维掩码仍无法形成正确三维实例，问题在回写和融合；如果可以，问题在种子约束的二维复核。完成这项分解前，不应再讨论类别尺寸先验的效果。
