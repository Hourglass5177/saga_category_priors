# SAGA 全类别三维候选二维复核：基线标准

更新日期：2026 年 9 月 3 日

## 这轮到底研究什么

老师这次把问题说得很具体：三维分支找到一个可能的小物体以后，不要立刻相信，也不要只看全场平均指标。应当把这个三维候选重新放回它最清楚的二维图像中，让现有的开放词汇检测和分割模型再看一次。若候选通过多视角复核，就保留；若复核不支持它，就撤回。与此同时，应专门统计这些分支候选究竟救回了多少原基线漏掉的物体，又引入了多少错误实例。

类别先验在本轮只有一个非常窄的作用：决定二维复核时应当看多大的图像范围。所有类别共用一个典型物理尺寸是 `global` 条件；按照候选预测类别读取典型物理尺寸是 `class` 条件。它不改变三维候选的成员，不重做聚类，也不替候选改类别。

因此，本轮不是重建一条自动实例分割主干，也不是继续研究旧的三维尺寸罚分。它是老师兼容自动流程上的一次受控二维复核实验。

## 基线身份

本轮基线不是公开 SAGA 的“官方自动实例基线”。公开 SAGA 的主要任务是提示式三维分割，并没有给出当前这套 ScanNet 自动实例流程的官方结果。这里使用的是老师交付原型逐步演化出的自动流程，并保留已经核实的两项正确性修复：最大贡献高斯使用 `alpha × T_prev`，以及最终预测满足单一输出合同。

实验基线固定为：

- 同一个全 SAGA20 分支候选库；
- 同一个 `global_pre_knn` 起点；
- 同一套全场 256 近邻投票、10 点过滤、最终二维类别投票和输出合同；
- 同一份 2k 特征、30k 三维高斯、相机、图像、二维掩码和训练集统计；
- 固定的 32 类开放竞争词表，其中只有 SAGA20 目标类别可以导出为实例。

老师兼容流程的内部投票仍可能产生 32 类词表中的非目标类别；正式 `output.json` 会统一投影到 SAGA20。所谓 B0/B1 机械复现，指在应用同一 SAGA20 输出投影、贡献映射修复和输出合同之后复现，不等于旧仓库未经修正的 28 类原始 JSON 字节一致。

全类别候选库是当前实验性全类别分支，不得称为老师原始的 7 类或 8 类小物体分支。`raw`、`global` 和 `class` 三个条件必须逐字节读取同一候选库，不得分别重跑候选生成。

## 四个比较条件

| 条件 | 含义 |
| --- | --- |
| `B0` | 不启用全类别分支的老师兼容自动流程，用来定义原流程漏掉的真实物体。 |
| `raw` | 全类别分支候选全部按现有方式进入旧后处理，不做二维复核。 |
| `global` | 对候选库中所有至少有一个可用投影视角的候选做复核，只接纳通过复核者；所有类别使用同一个全局典型尺寸裁图。 |
| `class` | 复核完全相同的候选，只把裁图所用尺寸换成候选预测类别的典型尺寸；缺失类别回退全局值。 |

三个核心差值分别回答三个不同问题：

- `global − raw`：把三维候选放回二维重新检查，本身有没有减少错误实例；
- `class − global`：逐类别典型尺寸是否比全局统一尺寸提供了额外帮助；
- `class − B0`：整个分支最终是否真的救回了原流程漏掉的目标。

本轮只运行固定的 8 个开发物理场景，不自动扩到 24 或 48 场景，也不设置根据结果自动停走的门槛。完整数字和案例交给人判断。

## 候选与来源追踪合同

候选库必须固定并记录候选编号、原始高斯成员、分支类别、`global_pre_knn`、高斯点顺序和生成参数。投影时只能使用候选的原始成员，不能使用经过近邻扩张后的最终掩码。

新候选库必须内嵌按顺序计算的高斯 XYZ、2k 关联/语义特征、标签特征和 `global_pre_knn` 指纹，并记录完整生成参数与 SAGA20 分支表。早期候选库缺少这些指纹，不能用于本实验。DEV8 每个场景在当前基线提交下只生成一次新候选库；同一次 B0 运行同时保存 `global_pre_knn` 和候选库。生成完成后立即冻结，`raw/global/class` 只能只读复用，绝不分别重跑 HDBSCAN。

老师兼容流程中的 HDBSCAN 原始核心点经过“向中心重新分配”后，历史数据里可能出现原始核心不再属于最终完整候选的情况。本轮不修这层聚类，也不得假设 `raw core` 是 `full` 的子集；二维回投统一使用冻结候选库里的 `branch_full` 原始成员，核心点只作诊断。

候选是否“最终存活”仍以真实进入 `output.json` 为准：它必须经过 KNN、10 点过滤、最终二维投票、SAGA20 类别筛选和统一输出合同。仅仅通过 `post_filter` 不算。但是，是否接受二维复核不能再由最终存活状态决定；所有具有可用投影视角的候选都必须先独立完成复核。

每个分支实例要保存稳定的来源链：

```text
candidate_id → raw internal label → final export id
```

只有能唯一追到某个候选时，最终实例才可写入 `origin=category_branch` 和 `source_candidate_id`。来源不明确的实例只能记入歧义诊断，不能硬指定一个候选编号。

三个条件的接纳集合固定为：`raw` 接纳全部候选；`global` 和 `class` 只接纳各自复核通过的候选。没有可用投影视角的候选在两种复核条件中都视为未确认。三者都从同一个 `global_pre_knn` 开始重放，因此最终分支实例必然来自该条件实际接纳的候选，不存在未经复核后意外出现的分支实例，也不再维护两套互相混淆的统计口径。

## 投影与裁图合同

每个待复核候选使用修正后的最大贡献高斯图投影到训练视角。只有 `id >= 0` 且贡献权重大于零的像素有效。旧的、没有绑定渲染实现身份的 contributor 缓存不得直接复用。

视角按候选投影像素数从大到小排列，最多取 3 个；投影少于 4 像素的视角弃用；并列时按图像名排序。批量实验前必须先输出一张真实 RGB 图与候选轮廓叠加图，人工确认相机、图像方向和 contributor 坐标完全一致。

裁图遵循新指导给定的固定公式：

```text
s_prior = s_candidate × d_prior / max(d_candidate, 1e-4)
crop_side = 1.5 × max(s_candidate, s_prior)
crop_side = min(crop_side, max(image_width, image_height))
```

其中 `s_candidate` 是该视角候选投影框的最长像素边，`d_candidate` 是候选米制主成分包围盒的三轴对角线；`d_prior` 在 `global` 中读取训练集全局中位数，在 `class` 中读取预测类别中位数。裁图中心为投影像素质心，越界区域填中性灰，不拉伸原图。裁图边长最多为原图长边；超过整图以后新增区域只有灰色填充，不能提供额外视觉信息。每次必须记录裁图是否触发 `crop_capped`。

这个公式是本项目待检验的工程假设，不是论文已经证明的定律。多尺度裁图和放大小目标有文献支持，但“物理对角线按比例换算像素裁图”仍可能受深度、姿态、遮挡和候选残缺影响。因此必须旁报实际裁图边长、越界比例、候选与先验尺寸比和极端裁图数量，不能把公式失败误写成所有类别先验都无效。

所有像素框采用左闭右开坐标，质心四舍五入到最近整数像素；浮点框先向外取整，确保原投影完整落入裁图。虚拟填充后的裁图再交给 GroundingDINO 自身的标准缩放。上述“原图长边”上限已经冻结，不得根据显存或结果临时改变。

## 二维复核合同

只使用仓库已有的 GroundingDINO Swin-T OGC 和 SAM ViT-H。每个场景各模型只初始化一次；两个实验条件共用相同图像、视角、32 类顺序和固定阈值：box 0.35、text 0.35、NMS 0.8。

GroundingDINO 每次都看完整 32 类词表，而不是只询问候选原类别。只保留检测框与候选投影框相交的结果，并对每个结果计算 `检测置信度 × coverage`；每个视角只选择该乘积最高的一个检测，再判断它是否确认候选。这样，当最高证据属于其他类别时，不能绕过它去挑一个更弱的同类结果完成自我确认。SAM 掩码与候选投影的覆盖率定义为：

```text
coverage = 交集像素数 / 候选投影像素数
```

一个视角只有在检测类别等于分支类别且覆盖率至少 0.5 时确认候选。1 个可用视角要求 1 票；2 个视角要求 2 票；3 个视角要求至少 2 票；没有可用视角则不确认。

覆盖率是单向指标，大掩码可能覆盖候选却同时包含大量背景。为了忠实执行固定方案，本轮不临时增加二维 IoU 门槛，但必须旁报 SAM 与候选投影的二维 IoU、SAM/候选面积比和超大掩码比例，并展示代表性案例。这样才能判断误确认来自候选、裁图还是覆盖率定义。

复核结果只决定候选是否进入同一个旧后处理。它不得修改候选几何、分支类别、最终投票类别或输出置信分数，也不得进行保护式 KNN、KNN 后插回、halo 补全或第二轮复核。本轮所谓“迭代验证”准确说是一次回投—复核—重放循环，而不是无限循环到满意为止。

## 评价标准

主指标不是把所有物体混在一起的总 mAP，而是分支对 B0 漏检物体的救回质量。

在 IoU 0.25 和 0.50 两个阈值下，分别用 B0 和真实标注做同类别、严格大于阈值的一对一匹配。没有被 B0 命中的真实物体构成该阈值自己的 `missed_gt`。然后只拿最终能够追溯到分支候选的实例去匹配 `missed_gt`：

- 真阳性：救回一个 B0 漏检物体；
- 假阳性：没有救回任何漏检物体，包括重复检测 B0 已找到的对象；
- 假阴性：仍未被分支救回的 B0 漏检物体。

据此计算救回准确率、召回率和 F1。匹配必须一对一，同一个真实物体不能被多个预测重复计功。重复 B0 检测与完全无匹配的幻觉实例还要分别统计，便于解释错误来源。

分层只保留两种，完整冻结值见 `evaluation_strata.json`：

- `small` 是实例级定义：真实实例米制包围盒对角线不超过 `0.886095877588466 m`。该值是已登记 ScanNet-train SAGA20 统计的全局、按物理场景平衡后的第 25 百分位；它不是“小类别名单”。
- `tail` 是类别级定义：按同一训练集实例数从少到多排列，固定取 `ceil(20/3)=7` 类；同频时按规范类别名升序破并列。冻结名单是 `socket、speaker、switch、fan、refrigerator、cup、phone`。

同时报告 `small ∩ tail`。小物体指标中，正确命中中大型同类物体的预测应忽略，而不是错误算作小物体假阳性；其余未命中小物体漏检集合的预测才算假阳性。

每个场景独立计算，同时给出场景等权均值和汇总计数，不能把所有候选当作相互独立样本。整体 SAGA20 指标只作辅助：主协议是 ScanNet 的 0.50 至 0.90 九档平均精度，AP25 单列；0.50 至 0.95 十档仅作历史对照，不得称为官方主协议。

## 运行前必须通过的技术检查

这些检查只判断实现是否可信，不根据科学结果决定停走：

1. `B0`、候选库、30k RGB 高斯和 2k 特征的点数与 XYZ 顺序一致。
2. 图像解析不会因模糊文件名静默选错相机对应的 RGB。
3. 最大贡献高斯确实使用 `alpha × T_prev`，空像素返回 `-1/0`。
4. 一张真实 RGB 与投影轮廓叠加图人工确认对齐。
5. `raw/global/class` 的候选编号、原始成员和基础分数完全同源。
6. 没有复核时，重放结果逐点复现冻结的 `raw` 输出。
7. 输出不存在未声明实例、负实例 metadata 或重复高斯所有权。
8. 真实标注只进入独立评价和事后案例选择，不进入候选、投影、裁图、模型推理或重放。
9. 启动进程必须设置 Hugging Face 和 Transformers 离线模式，并预先确认 BERT tokenizer、GroundingDINO 和 SAM 权重均在本机；缓存缺失时直接报错，不得隐式联网下载。
10. 最终二维类别投票使用的 `masks_path` 和 `labels_path` 必须显式传入、确为目录，并且整场至少找到一组成对文件。个别视角可以同时缺失并作为“不知道”跳过；整场零配对必须立即报错，不能生成全零投票或空预测。

## 本轮明确不做什么

- 不训练或下载任何模型。每场只允许在当前基线下生成一次带完整指纹的新候选库；冻结后不得为不同条件重跑 HDBSCAN 或改变候选池。
- 不再启动 ObjectBank、跨视角跟踪、几何超点、尺度门控或 V3–V10 流程。
- 不使用旧的三维尺寸罚分、平滑度、支持量总分或阈值恢复。
- 不搜索检测阈值、裁图倍率或上下文大小。
- 不让 `global` 和 `class` 使用不同的最终 AP 分数。
- 不自动扩展到 24 或 48 场景。

## 参考工作的边界

[公开 SAGA](https://github.com/Jumpat/SegAnyGAussians) 是提示式三维高斯分割系统，不是当前自动 ScanNet 实例流程的数值基线。

[OpenMask3D](https://proceedings.neurips.cc/paper_files/paper/2023/file/d77b5482e38339a8068791d939126be2-Paper-Conference.pdf) 会把三维实例投到多个视角，选择可见度高的图像并在多尺度裁图中提取语义特征，说明“三维候选回到清晰二维视角再识别”是合理的技术路线。[Open3DIS](https://openaccess.thecvf.com/content/CVPR2024/papers/Nguyen_Open3DIS_Open-Vocabulary_3D_Instance_Segmentation_with_2D_Mask_Guidance_CVPR_2024_paper.pdf) 将二维掩码提议与三维提议结合，进一步说明二维证据可以补充三维候选；它并不直接证明本实验一定能救回小物体。[SAHI](https://arxiv.org/abs/2202.06934) 说明切片和放大能够改善小目标检测。[Grounding DINO](https://arxiv.org/abs/2303.05499) 支持用完整类别词表做开放集合竞争。ScanNet 的[官方实例评价脚本](https://github.com/ScanNet/ScanNet/blob/master/BenchmarkScripts/3d_evaluation/evaluate_semantic_instance.py) 则规定了 0.50 至 0.90 九档、AP25 和最小 100 点等基本口径。

这些工作支持总体方向，却没有替本实验验证固定裁图公式、覆盖率 0.5 或多数票规则。上述数值仍是本轮冻结的、需要用 DEV8 和真实案例检验的工程选择。
